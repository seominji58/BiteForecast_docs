## 1. 시스템 구성

```
[iOS 앱 (SwiftUI)]  ──HTTPS/JSON──▶  [FastAPI 서버]  ──▶  [SQLite (개발) / 운영 DB 별도 검토]
   BiteForecast_frontend                BiteForecast_backend        ▲
                                           │  배치 수집기(스케줄러) ──┘
                                           ▼
                         국립해양조사원 조석예보 / 조위관측소 / 해양관측부이, 기상청 API허브
```

- **공공 API는 반드시 서버에서만 호출한다** (NFR-03: 인증키 앱 하드코딩 금지 → 서버 환경변수).
- 서버는 **배치 수집 + 캐시** 구조: 대상 관측소 데이터를 주기적으로 받아 DB에 저장하고, 앱 요청은 DB에서 응답한다 (NFR-06 3초 목표, 쿼터 보호).
- **사용자 식별 `[가정]`**: MVP는 로그인 없이 **기기 UUID(Keychain 저장)** 를 `X-Device-Id` 헤더로 보내 서버에 저장한다. 포인트 중복 방지·환경정보 연결을 서버에서 일관되게 처리하기 위해서다. 계정(FR-16)은 LATER.

## 3. 화면 명세

공통 상태: 모든 화면은 **로딩 / 빈 상태 / 오류(재시도 버튼)** 를 갖는다 (NFR-04). 모든 정보 요소에 텍스트 라벨을 붙이고 Dynamic Type을 지원한다 (NFR-05).

### SCR-01 홈 / 장소 선택
| 요소 | 내용 | API |
|---|---|---|
| 해역 탭 | MVP 지원 해역 2~3곳 | `GET /regions` |
| 장소 검색 | 이름 검색, 결과 목록 (장소 타입·규제 상태 배지) | `GET /places?q=&region_id=` |
| 즐겨찾기 | 상단 고정 (SHOULD) | `GET /me/favorites` |
| 최근 조회 | 기기 로컬(UserDefaults) 최근 5건 | - |
| A/B 슬롯 + 날짜 | 장소 2곳 + 날짜 선택 후 [비교하기] | - |

- [비교하기]는 **A·B 모두 선택되고 서로 다를 때만 활성화**된다 (FR-02). 같은 장소를 고르면 "이미 선택한 장소입니다"를 띄운다.
- 날짜 선택기는 **조회 가능 범위**(`GET /meta/date-range`)만 선택할 수 있게 한다.
- 검색 결과가 없으면 "지원 지역이 아닙니다"를 표시한다 (FR-01).

### SCR-02 A/B 환경 비교
| 요소 | 내용 |
|---|---|
| 장소 카드 A/B | 장소명, 기준 관측소명, **관측소 거리(km)**, 규제 상태 배지 |
| 조석 표 | 만조·간조 시각/조위(cm), 장소별 2열 |
| 조위 그래프 | 시간별 예측 조위, **동일 시간축(00~23시)**, A/B 2계열 |
| 파고·풍속 그래프/표 | 시간별 값, 단위(m, m/s), 값 없음 구간은 끊어서 표시 (보간 금지) |
| 자료 배지 | 계열마다 `예보` / `실측` 배지 + 기준 시각 |
| 시간대 필터 (SHOULD) | 최대 풍속·파고 입력 → 조건 충족 시간대 하이라이트 |
| 고지 문구 | "실제 입질·조과를 보장하지 않으며 출조 전 공식 특보와 현장 출입 제한을 확인하세요." |
| [이 장소에 기록 남기기] | SCR-04로 이동 (장소·날짜 프리필) |

API: `GET /compare?place_a=&place_b=&date=`

### SCR-03 자료 상세
계열별 **출처 기관, 데이터셋명, 예보/실측 구분, 관측소명·좌표, 장소-관측소 거리, 제공 시각(issued/observed_at), 마지막 조회 시각(fetched_at)** 을 보여준다. 좌표가 없으면 "거리 확인 불가"로 표시한다 (FR-07, NFR-02). 규제정보 상세(F-REG)도 이 화면의 탭으로 둔다.

### SCR-04 낚시일지 작성/수정
| 필드 | 필수 | 검증 |
|---|:-:|---|
| 출조 일시 | ● | 미래 시각 불가 |
| 장소 | ● | 지원 장소 중 선택 |
| 어종 | | 어종 코드 목록 + 기타(자유입력) |
| 마릿수 | | 정수 0~999, 음수 금지 |
| 최대 길이(cm) | | 0 < x ≤ 300 `[가정]`, 소수 1자리 |
| 미끼 / 채비 | | 각 50자 |
| 메모 | | 1000자 |
| 사진 (SHOULD) | | 최대 3장 `[가정]`, JPEG/HEIC, 장당 10MB, EXIF 위치 제거 |

- 저장 후 **획득 포인트 토스트**를 띄운다 (예: "+30P 획득 · 칭호까지 20P"). 응답의 `point_delta`를 쓴다.
- 삭제할 때는 확인 시트를 띄운다: "삭제 시 이 기록으로 받은 포인트가 회수됩니다."

### SCR-05 내 기록
일지 목록(최신순), 상세(입력값 + **당시 환경정보: 출처/예보·실측 구분과 함께**), 대시보드(SHOULD): 출조 횟수, 어종별 마릿수, 최대어, 장소별 기록. 대시보드에는 **표본 수·기록 기간을 함께 표시**하고, 인과관계나 확률을 표현하는 문구는 쓰지 않는다 (FR-13).

### SCR-06 활동·칭호
현재 칭호, 총 포인트, 다음 칭호까지 남은 포인트(진행 바), 포인트 내역(사유·증감·일시).

### SCR-07 설정·법적 안내
데이터 출처 목록, 이용약관, 개인정보 처리방침, 문의처, **내 데이터 전체 삭제** (`DELETE /me`).

## 4. 기능 상세 명세

### F-PLACE 해역·장소 목록 (FR-01)
- 장소 데이터는 **사전 구축 시드 데이터**다 (관리자가 JSON/CSV로 적재). 장소마다 기준 조석 관측소와 해양관측 지점을 1개씩 매핑한다 (`place_station`).
- 매핑할 때 장소-관측소 **대권거리(Haversine, km)** 를 미리 계산해 저장한다.
- 장소 목록에 "낚시 허용구역"을 보증하는 문구를 쓰지 않는다. 규제 상태 배지만 표시한다 (F-REG).

### F-COMPARE / F-TIDE / F-OCEAN / F-SOURCE (FR-02~05, 07)
**처리 로직 (서버)**
1. A·B 장소를 검증한다: 둘 다 존재해야 하고, 서로 달라야 하고, 날짜가 조회 가능 범위 안이어야 한다. 하나라도 어기면 `400`.
2. 장소마다 매핑된 관측소에서 아래 계열을 조회한다.
   - `tide_forecast`: 해당 날짜의 시간별 예측 조위와 만조/간조 (항상 `kind=forecast`)
   - `ocean_obs`: 파고·풍속 실측. **조회 날짜 ≤ 오늘일 때만** 포함하고, 오늘이면 현재 시각까지만 포함한다.
   - `ocean_forecast`: 파고·풍속 예보 (기상청 등에서 확보한 경우에만)
3. 실측과 예보는 **서로 다른 계열(series)로 분리**해서 응답한다. 한 배열에 섞지 않는다 (TC-03).
4. 값이 없는 시각은 `null`로 둔다. 0으로 채우지 않는다 (TC-02). 계열 자체가 없으면 `status: "unavailable"`로 응답한다.
5. 보간하지 않는다. 원본 시각을 그대로 내보내고, 시간축 정렬은 클라이언트가 한다.

**응답 예시** `GET /compare?place_a=12&place_b=31&date=2026-11-08`
```json
{
  "date": "2026-11-08",
  "places": [
    {
      "place": {"id": 12, "name": "OO방파제", "region": "태안"},
      "regulation": {"status": "UNVERIFIED"},
      "series": [
        {
          "metric": "tide_level", "unit": "cm", "kind": "forecast", "status": "ok",
          "source": {"agency": "국립해양조사원", "dataset": "조석예보", "station_id": "DT_0001",
                     "station_name": "OO", "distance_km": 4.2},
          "issued_at": "2026-11-05T00:00:00+09:00", "fetched_at": "2026-11-05T03:10:00+09:00",
          "points": [{"t": "2026-11-08T00:00:00+09:00", "v": 312}, {"t": "2026-11-08T01:00:00+09:00", "v": null}]
        },
        {"metric": "tide_extreme", "kind": "forecast", "status": "ok",
         "extremes": [{"t": "2026-11-08T05:42:00+09:00", "type": "high", "v": 640}]},
        {"metric": "wave_height", "unit": "m", "kind": "observed", "status": "unavailable",
         "reason": "FUTURE_DATE"}
      ]
    }
  ],
  "disclaimer": "실제 입질·조과를 보장하지 않으며 출조 전 공식 특보와 현장 출입 제한을 확인하세요."
}
```

**물때 단계** (FR-03): 계산 기준을 확정하기 전까지 MVP에서는 **표시하지 않는다** `[가정]`. 조위(cm)와 물때를 혼동하지 않는다.

### F-FILTER 시간대 필터 (FR-06, SHOULD)
- 클라이언트가 계산한다. 입력은 최대 풍속(m/s)과 최대 파고(m)이고 기본값은 `[가정]` 8m/s, 1.0m.
- 시각 t는 **두 값 모두 존재하고 임계값 이하**일 때만 "조건 충족"이다. 하나라도 `null`이면 판정에서 제외("판정 불가" 회색 표시).
- 문구는 "선택한 조건을 충족합니다"만 쓴다. **"안전", "최적", "추천"은 금지**한다.

### F-JOURNAL 낚시일지 (FR-08)
- `POST/PUT/DELETE /journals`. 모든 요청은 `X-Device-Id` 소유자 기준으로 처리한다.
- **삭제는 소프트 삭제**(`deleted_at`)로 한다. 연결된 환경 스냅샷과 사진은 함께 삭제 처리하고, 포인트는 재계산한다 (F-POINT).
- 저장·수정·삭제 응답에 `{journal, point_delta, total_points, title}`를 포함한다.

### F-PHOTO 사진 (FR-09, SHOULD)
- `POST /journals/{id}/photos` (multipart). 서버에서 **EXIF를 제거**하고 리사이즈(장변 2048px)한 뒤 저장한다.
- 저장소는 MVP에서 로컬 디스크 `[가정]`이고, 운영 단계에서 오브젝트 스토리지를 검토한다. 사진 URL은 소유자 인증으로만 접근한다 (기본 비공개).

### F-ENVLINK 환경정보 연결 (FR-10)
- 일지를 저장하거나 출조 일시·장소를 바꾸면, 서버가 해당 장소 관측소의 **출조 시각 ±1시간 내 가장 가까운 값**을 지표마다 찾아 `journal_env_snapshot`에 저장한다. `[가정]` ±1시간
- 스냅샷마다 `kind`(forecast/observed), `source`, `value_time`(원본 값의 시각), `linked_at`을 저장한다.
- 값을 찾지 못하면 `value=null`로 저장한다. 과거 데이터가 늦게 수집되면 배치가 `null` 스냅샷을 다시 채운다.
- 화면 표기는 "당시 인근 관측소 기록"으로 하고, 현장 조건이었다고 단정하지 않는다.

### F-POINT 활동 포인트 (FR-11)
**적립 규칙**
| 사유 코드 | 조건 | 포인트 | 중복 방지 키 |
|---|---|---:|---|
| `JOURNAL_CREATED` | 일지 작성 | +10 | `journal_id` |
| `DETAIL_FILLED` | 어종 **및** 길이 입력 | +5 | `journal_id` |
| `PHOTO_ATTACHED` | 사진 1장 이상 | +5 | `journal_id` |
| `FIRST_PLACE` | 해당 장소의 첫 기록 | +15 | `user_id + place_id` |
| `PERSONAL_BEST` | 같은 어종의 기존 최대 길이를 초과 | +20 | `journal_id` |

**구현 방식: 원장 재계산(derive) 방식**
- 일지가 생성·수정·삭제될 때마다 **해당 사용자의 활성 일지 전체로 기대 포인트 이벤트 집합을 다시 계산**한다. 기존 원장과 비교해 없어진 이벤트는 `-` 정정 행, 새 이벤트는 `+` 행으로 추가한다 (원장은 append-only).
- 이 방식으로 TC-05(재저장 시 중복 지급 없음)와 TC-06(삭제/정정 시 재산정)이 구조적으로 보장된다.
- `FIRST_PLACE`: 장소별 **가장 이른 출조 일시**의 활성 일지 1건에 귀속된다. 그 일지가 삭제되면 다음 일지로 이전된다.
- `PERSONAL_BEST`: 같은 어종의 일지를 출조 일시순으로 보면서 **직전까지의 최대 길이를 초과**하면 지급한다. 그 어종의 첫 기록은 "갱신"이 아니므로 미지급 `[가정]`.
- 하루 상한: MVP에서는 **미적용** `[가정]`. 설정값(`POINT_DAILY_CAP`)으로 나중에 켤 수 있게 둔다.
- 포인트는 앱 내 가상 보상이며 교환 기능은 없다.

### F-TITLE 칭호 (FR-12)
| 칭호 | 최소 포인트 |
|---|---:|
| 입문 | 0 |
| 초보 | 50 |
| 주말 | 150 |
| 베테랑 | 300 |
| 바다의 고수 | 600 |

- `title` 기준 테이블에서 조회한다 (명칭 변경 가능). 현재 칭호 = `min_points ≤ 총점`인 칭호 중 최댓값.
- 총점이 줄면 칭호도 강등된다 (재계산 일관성). 승급하면 응답에 `title_changed: true`를 넣고, 앱은 축하 모달을 띄운다.

### F-DASH 대시보드 (FR-13, SHOULD)
`GET /me/stats`: 출조 횟수, 기록 기간(첫~마지막), 어종별 마릿수 합, 어종별 최대어, 장소별 방문 수. 환경조건 분포는 표본 수와 함께 표시하는 SHOULD 항목이다.

### F-FAV 즐겨찾기 (FR-14, SHOULD)
`PUT/DELETE /me/favorites/{place_id}`. 지원이 중단된 장소(`place.is_active=false`)는 목록에 "지원 중단"으로 표시한다.

### F-REG 규제정보 (FR-17~20)
- MVP는 해역 2~3곳의 공식 고시를 **수동 조사**해 `restriction` 테이블에 시드로 넣는다.
- **상태값 (4단계)**
  | 코드 | 표시 | 조건 |
  |---|---|---|
  | `PROHIBITED` | 낚시 금지 확인 | 유효한 공식 금지 고시가 있고, 출조일이 적용 기간 안에 있음 |
  | `CONDITIONAL` | 조건부 제한 확인 | 기간·시간·행위·구간 제한 근거가 있음 |
  | `OFFICIALLY_OPEN` | 공식 개방 확인 | 관리기관이 명시적으로 허용한 근거가 있음 (범위·유효기간 표시) |
  | `UNVERIFIED` | 확인되지 않음 | **기본값.** 자료 없음, 오래됨, 판정 불가 |
- **판정 로직** `evaluate(place, date)`
  1. 해당 장소의 restriction 중 `valid_from ≤ date ≤ valid_to`(또는 `valid_to` 없음)이고 해제되지 않은 것만 남긴다.
  2. `restriction_type`(낚시/출입)별로 **각각** 상태를 낸다. 두 가지가 동시에 있으면 둘 다 표시한다 (10.6).
  3. 금지 자료가 없다는 이유로 `OFFICIALLY_OPEN`을 주지 않는다. 명시적인 허용 근거가 있어야만 준다.
  4. `geometry_accuracy`가 낮거나 경계 부근이면 자동 판정하지 않고 `UNVERIFIED`와 함께 "수동 검토 필요"를 표시한다.
  5. `last_checked_at`이 30일 넘게 지났거나 갱신에 실패했으면 "최신 여부 미확인" 경고를 붙인다 `[가정]` 30일.
- 응답에는 기관명, 고시번호, 원문 URL, 적용 구역·기간, 발행일, 확인일을 포함한다 (FR-19).
- 비교 화면에서 `PROHIBITED` 장소에는 빨간 경고 배너를 띄우고, `UNVERIFIED` 장소에는 "합법 여부 미확인" 문구를 표시한다 (FR-20).

### F-REPORT 오류 신고 (FR-21, SHOULD)
`POST /places/{id}/regulation-reports`로 신고하면 `pending` 상태로 저장된다. **법적 상태는 바뀌지 않는다.** 관리자 검토 화면은 LATER로 두고 MVP에서는 DB에서 직접 조회한다.
