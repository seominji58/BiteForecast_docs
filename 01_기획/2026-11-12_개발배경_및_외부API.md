# 입질예보 — 개발 배경과 사용 중인 외부 API (2026-11-12)

## 1. 개발 배경 및 기획 의도

### 낚시의 즐거운 순간을 다시, 그리고 함께

누구에게나 오래도록 기억에 남는 순간이 있다. 누군가에게는 여행이고, 누군가에게는 소중한 사람과 함께한 시간일 것이다. 나에게는 바다를 바라보며 낚싯대를 드리우고, 입질을 기다리던 시간이 그런 기억으로 남아 있다.

낚시는 단순히 물고기를 잡는 활동이 아니다. 출조를 준비하는 설렘부터 바다에서 보내는 여유로운 시간, 기다림 끝에 찾아오는 짜릿한 손맛, 그리고 함께한 사람들과 나누는 이야기까지. 그 모든 과정이 낚시를 다시 찾게 만드는 즐거움이라고 생각한다.

이러한 경험을 떠올리며, 낚시를 좋아하는 사람들이 자신의 추억과 경험을 기록하고 서로 공유할 수 있는 공간을 만들고 싶었다.

하지만 실제로 낚시를 준비하려면 물때, 파고, 풍속, 수온, 기상특보 등 다양한 정보를 여러 사이트에서 각각 확인해야 하는 불편함이 있다. 특히 낯선 지역으로 출조할 때는 어디로 가야 할지, 어떤 어종을 만날 수 있을지 알아보는 과정에도 많은 시간이 필요하다.

**입질예보는 이러한 불편함을 줄이면서, 낚시를 좋아하는 사람들의 경험과 즐거움을 연결하기 위해 기획한 서비스이다.**

기상청과 국립해양조사원 등에서 제공하는 공공데이터를 활용해 출조에 필요한 정보를 한곳에서 확인할 수 있도록 하고, 이용자들이 자신의 조황과 낚시 경험을 기록하고 공유할 수 있는 커뮤니티를 함께 제공하고자 한다.

단순히 정보를 조회하고 끝나는 앱이 아니라, 출조를 준비하는 순간부터 낚시를 즐기고 돌아온 이후까지 하나의 경험으로 이어지는 공간을 만드는 것이 목표이다.

**오늘의 바다를 확인하고, 내일의 출조를 기대하며, 오래도록 기억하고 싶은 순간을 함께 나누는 곳.**

그것이 입질예보가 지향하는 서비스의 모습이다.

### 공공데이터를 다루는 원칙
- 기관 발표값을 그대로 전달하고, 앱이 조황·안전 점수를 따로 만들지 않는다
- 자료가 없으면 0 이나 추정값으로 채우지 않고 「자료 없음 · 확인 불가」로 보여준다
- 공식 바다낚시지수 「좋음」도 실제 조과나 출조 안전을 보장하지 않는다고 함께 알린다
- 커뮤니티 조황은 사용자가 남긴 실제 기록만 보여준다 (가짜 조황·사진 없음)

## 3. 주요 정보와 용어 풀이

앱에서 보여주는 정보가 무슨 뜻인지, 낚시하는 사람이 어떻게 보면 되는지 정리한다. 앱에서도 같은 내용을 볼 수 있다 (홈 「오늘의 낚시 정보」 칸을 누르거나, 낚시터 상세의 「ⓘ ○○란?」).

### 3-1. 공식 바다낚시지수

**국립해양조사원이 지점·어종별로 「오늘 바다가 그 물고기를 낚기에 좋은 조건인지」를 5단계로 발표하는 지수**이다.

| 항목 | 내용 |
|---|---|
| 바탕 자료 | 물때(조석)와 파고·수온·풍속 같은 바다 예측값. 지수와 함께 그날의 파고·수온·풍속 범위도 발표된다 (앱 상세 화면 「공식 발표 환경 범위」) |
| 등급 | 매우좋음 · 좋음 · 보통 · 나쁨 · 매우나쁨 |
| 지점 | 전국 49곳 — 갯바위 포인트 34 · 선상 15 |
| 어종 | 우럭 · 감성돔 · 농어 · 돌돔 · 벵에돔 · 참돔 · 볼락 · 열기 (8종) + 기타어종 · 어종 공통 |
| 기간 | 오늘부터 3일은 오전·오후, 이후 7일째까지는 하루 단위 |

꼭 알아둘 점
- 물고기가 실제로 있는지·잡히는지를 알려주는 것이 아니라 **바다 조건이 그 어종 낚시에 얼마나 맞는지**를 나타낸다. 「좋음」이어도 조과나 출조 안전을 보장하지 않는다
- 지수는 **발표 지점 기준**이다. 근처 일반 낚시터에 보이는 지수는 가까운 지점(10km 이내)의 참고값이며, 그 낚시터에서 해당 어종이 잡힌다는 뜻이 아니다
- 앱이 만든 점수가 아니라 기관 발표값을 그대로 보여준다. 발표되지 않은 어종·시간대의 등급은 만들지 않는다

## 4. 차별성 — 입질예보만의 강점

> 한 줄 소개: **공식 데이터로 오늘의 바다를 믿고 확인하고, 잡고 싶은 어종에서 출조 계획·조황 기록까지 하나로 이어지는 낚시인의 공간**

| # | 기존 방식의 불편 | 입질예보는 | 구현 근거 |
|---|---|---|---|
| 1 | 물때·파고·풍속·특보를 여러 사이트·앱에서 따로 확인 | **한 화면에서** 날짜·지역별로 확인 | 기상청 단기예보·특보 + 국립해양조사원 조석·부이·낚시지수를 매시 자동 수집해 한 API 로 제공 |
| 2 | 「어디서, 무엇을」 찾는 데 시간이 걸림 | **어종에서 시작하는 탐색** — 잡고 싶은 어종 → 공식 지수 지점 → 포인트 → 출조계획 | 공식 바다낚시지수 8종·49지점 오전/오후 등급, 홈 어종 카드 → 포인트 보기 → 목표 어종 자동 입력 |
| 3 | 출처를 알 수 없는 점수·추천 | **기관 발표값을 그대로**, 출처·발표 시각과 함께. 앱이 조황 점수를 만들지 않음 | 예보/실측 구분, 「○시 발표」 표시, 자료가 없으면 0 대신 「자료 없음」 |
| 4 | 낚시터 위치가 틀려 엉뚱한 바다 정보를 보는 위험 | **위치 정확도 검증** — 좌표가 의심되는 곳은 해황 연결·추천에서 제외 | 219곳 좌표 품질 등급(A~D)·검증 이력, 주소 API 대조, 근처 지점 지수는 「참고」로 구분 |
| 5 | 「특보 없음」인지 「확인 못 함」인지 알 수 없음 | **안전 정보는 보수적으로** — 확인 불가를 「없음」으로 표시하지 않음 | 특보 상태 세분화(해역 모름·자료 만료·수집 실패 구분), 지금 발효 기준 명시 |
| 6 | 파고·풍속 숫자만으로는 감이 안 옴 | **쉬운 말로 풀어서** — 「낮은 물결」「건들바람」「사리 무렵」 + 용어 풀이 | 세계기상기구 파랑 등급·보퍼트 풍력 등급·기상청 특보 기준으로 작성 |
| 7 | 정보 확인과 출조 준비·기록이 따로 놂 | **준비부터 기록까지 한 흐름** — 출조계획(날짜별 장소·예비 장소·준비물) → 그날 해황 요약 → 다녀와서 기록 | 출조계획 API·화면, 계획 장소에서 「기록 남기기」 연결 |
| 8 | 커뮤니티 조황의 신뢰도 | **믿을 수 있는 조황 커뮤니티** — 사진 인증 조황, 가짜 조황·사진 없음 | 관리자 사진 검토 후 인증·포인트·칭호, 테스트 계정 글 분리 |
| 9 | 개인 프로젝트는 운영이 멈추기 쉬움 | **저비용 자동 운영** — 서버·DB·수집이 사람 손 없이 계속 동작 | Fly.io(도쿄)·Supabase(서울)·GitHub Actions 매시 수집, 월 약 $2 수준 |

### 발표용 핵심 3가지
1. **어종 중심 탐색** — 「어떤 물고기를 잡으러 가세요?」에서 시작해 공식 낚시지수 지점과 출조계획까지 바로 이어진다
2. **믿을 수 있는 공공데이터** — 기관 발표값을 출처·시각과 함께 그대로, 위치가 의심되거나 자료가 없으면 솔직하게 「확인 불가」
3. **경험을 잇는 커뮤니티** — 출조 준비 → 낚시 → 인증 조황 기록·공유가 한 앱에서
