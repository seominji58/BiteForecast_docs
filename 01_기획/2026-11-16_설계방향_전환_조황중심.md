# 설계 방향 전환 — 「공공데이터 보여주기」에서 「낚시인 조황 중심」으로

> 작성 2026-11-16 · **방향 설계만 — 코드·DB 변경 없음**
> 계기: 사용자 피드백 「이게 서비스인지 공공데이터 뿌리기인지」
> 관련: [서비스 개선·커뮤니티 활성화 설계](2026-11-16_서비스개선_커뮤니티활성화_설계.md) (기능 단위 개선안. 이 문서는 그 위의 **방향**을 바꾼다)

## 1. 지금 문제

**지금 앱의 중심은 공공데이터다.**
- 홈: 바다 배경 → 어종 카드 → 오늘의 바다(파고·풍속·물때·특보 4칸)
- 지도: 낚시터 핀 + 공식 지수·해황
- 낚시터 상세: 특보 → 지수 → 파고·풍속·수온·물때 그래프 → (맨 아래) 이용자 조황
- 기록·커뮤니티·출조계획: 각자 다른 탭에 따로 있다

**그래서 다시 들어올 이유가 약하다.**
- 기상청·해양조사원 숫자는 바다타임·윈디·기상청 앱도 보여 준다. 우리만의 정보가 아니다
- 「오늘 어디서 뭐가 잡히나」라는 낚시인의 첫 질문에 답하지 못한다. 공식 지수는 바다 조건이지 조황이 아니다
- 이용자가 남긴 기록·조황이 화면 뒤쪽이나 다른 탭에 있어서, 남겨도 다른 사람에게 보이지 않는다 → 남길 이유도 약하다

**운영 DB 현황 (2026-11-16, 읽기만 함)**: 사용자 20 · 기록 7 · 글 9 (낚시터를 붙인 글 4) · 댓글 0. 대부분 테스트 자료다. **조황이 거의 없는 상태에서 시작한다**는 것을 전제로 설계한다.

## 2. 바꿀 방향 (한 줄)

> **「낚시인이 남긴 조황」이 앞, 공공데이터는 그 판단을 돕는 뒤.**
> 출조 전에는 남의 조황으로 고르고, 다녀와서는 내 기록이 남의 조황이 된다.

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 첫 질문 | 오늘 바다 어때? | **요즘 어디서 뭐가 잡혀?** |
| 화면 맨 위 | 파고·풍속·지수 | 최근 조황 (사진·어종·크기·언제) |
| 공공데이터 | 주인공 | 「가도 될까?」 확인용 — 특보·파고·물때 한 줄, 자세히는 펼쳐서 |
| 기록 | 내 보관함 | 남에게 보이는 조황의 원천 (공유 기본, 위치 공개 범위는 고를 수 있음) |
| 다시 오는 이유 | 날씨 확인 | 관심 낚시터·어종에 새 조황이 올라옴 |

## 3. 핵심 흐름

```
[출조 전] 요즘 조황 보기 (홈·지도·낚시터) → 갈 곳 고르기 → 바다·특보 확인 → 출조계획
     ↑                                                            ↓
[다시 옴] 관심 낚시터·어종 새 조황                          [출조 후] 30초 기록 (사진·어종·크기, 꽝도)
     ↑                                                            ↓
     └──────────── 다른 사람의 「요즘 조황」이 된다 ←── 공유 (위치 공개 범위 선택)
```

## 4. 화면별 바뀌는 것

### 4-1. 홈
- **맨 위**: 「이번 주 ○○ 해역 조황」 — 사진 카드 가로 줄 (어종·크기·낚시터 또는 지역·며칠 전)
- 그 아래: 어종 칩 → 그 어종 최근 조황
- 「오늘 바다」는 한 줄 요약으로 줄인다: `서해 · 특보 없음 · 파고 0.5m · 중조기` (누르면 자세히)
- **조황이 없을 때** (처음 상태): 「아직 이 해역 조황이 없어요 · 첫 조황을 남겨 주세요」 + 지금처럼 바다 정보 카드. 빈 화면을 만들지 않는다

### 4-2. 지도
- 핀 색·배지: **최근 7일 조황이 있는 낚시터**를 강조 (조황 수 배지). 조황 없는 곳은 연한 점
- 어종 칩 근거 순서: ① 이용자 조황(그 어종을 잡았다고 올린 곳) → ② 공식 지수 지점 → ③ 낚시터가 알린 대상 어종. 근거를 안내문에 표시 (지금 구현은 ②③만)
- 핀을 누른 카드 맨 위: 「최근 조황 3건 · 우럭 32cm (2일 전)」 → 그 아래 특보·파고 한 줄

### 4-3. 낚시터 상세
- 순서 변경: **이용자 조황 → 가도 될까(특보·파고·풍속·물때 요약) → 자세한 그래프(접기)**
- 「여기서 기록 남기기」 버튼을 위로

### 4-4. 기록
- 30초 기록: 사진 → 어종(사진에서 고르기 쉽게) → 크기·마릿수 → 저장. 장소는 출조계획·현재 위치로 미리 채움
- 저장할 때 「조황으로 공유」 **기본 켜짐**, 위치 공개 범위 기본 「지역만」 (포인트 노출 걱정 줄이기). 끄면 나만 보기
- 꽝 기록도 조황이다 — 「○○ 꽝, 바람 셈」도 남에게 쓸모 있다

### 4-5. 커뮤니티 탭
- 탭 이름을 **「조황」**으로 하고, 조황 글이 기본 목록. 질문·정보 글은 분류로 남긴다
- 관심 어종·지역 새 조황 알림 (2단계)

### 4-6. 줄이거나 뒤로 보낼 것
- 홈의 공공데이터 4칸 카드, 지도·상세의 숫자 나열 → 요약 한 줄 + 펼치기
- 「조건으로 찾기(내 기준)」 → 지도의 보조 칩으로만 (주인공 아님)
- 조건 비교 화면 → 상세에서만 들어가게 (메뉴에서 뺌 검토)

## 5. 처음 조황이 없을 때 (콜드 스타트)

**가짜 조황을 만들지 않는다** (운영자가 지어낸 글, 다른 사이트 글 퍼오기 금지).

1. **공공데이터가 빈자리를 채운다**: 조황이 없는 곳·해역은 지금 화면(바다 정보·지수)을 그대로 보여 준다. 조황이 생기면 그 위에 얹힌다
2. **기록을 남길 이유를 먼저 만든다**: 내 도감·최대어·칭호(이미 있음) + 「내 기록이 이 낚시터 첫 조황이 됐어요」
3. **꽝·짧은 기록 환영**: 사진 없이도 공유 가능 (인증·포인트는 사진 있는 기록만 — 지금 규칙 유지)
4. **지인 출조계획에서 시작**: 같이 간 사람 기록이 계획 안에서 서로 보이고, 공유하면 공개 조황이 된다
5. 숫자 목표 (출시 후 4주): 주간 공유 조황 30건, 기록→공유 50% 이상, 조황 있는 낚시터 20곳

## 6. 필요한 데이터·API (DB 표 추가 없이 시작 가능)

| 필요 | 방법 | DB 변경 |
|---|---|---|
| 낚시터별 최근 조황 요약 (건수·어종·최대 크기·마지막 시각) | `GET /places/catch-summary?days=7` — 공개 범위 「낚시터 이름」 글만 집계 | 없음 |
| 해역·시·도별 최근 조황 (「지역만」 공개 글 포함) | `GET /community/posts?sido=&days=` 확장 | 없음 |
| 어종별 조황 있는 낚시터 | 위 요약에 어종 필터 | 없음 |
| 공유 기본값 「지역만」 | 앱 기본값만 바꿈 | 없음 |
| 관심 낚시터·어종 알림 | 2단계, 푸시 토큰 표 필요 | **있음 (나중)** |

**지키는 원칙 (그대로)**: 조황은 이용자가 올린 사실일 뿐 예측이 아니다 · 공공데이터 값은 바꾸지 않는다 · 비공개 기록은 집계에 넣지 않는다 · 위치 공개 범위를 넘는 정보(정확한 좌표)는 보여 주지 않는다 · 특보가 있으면 조황이 좋아도 「가도 된다」고 하지 않는다

## 7. 단계

**1단계 — 화면 순서 바꾸기 (DB 변경 없음)**
1. 낚시터 조황 요약 API
2. 낚시터 상세: 이용자 조황 맨 위, 해황은 요약 + 펼치기
3. 지도: 조황 있는 핀 강조, 핀 카드 맨 위 조황, 어종 칩 근거에 ① 이용자 조황 추가
4. 홈: 맨 위 「이번 주 조황」 (없으면 지금 화면), 바다 정보 한 줄 요약
5. 기록 저장 화면: 공유 기본 켜짐·「지역만」 기본

**2단계 — 다시 오게 하기**
6. 커뮤니티 탭 → 「조황」 탭
7. 30초 기록 (장소 미리 채움, 사진에서 어종 고르기 쉽게)
8. 관심 낚시터·어종 새 조황 알림 (푸시, DB 변경 — 승인 후)

**3단계** — 100선 도전 등 기존 장기 과제

## 8. 정해 주셔야 할 것

1. **공유 기본값**: 기록 저장 때 「조황으로 공유」를 기본 켜기로 할지 (추천: 켜기 + 위치는 「지역만」 기본)
2. **탭 이름**: 「커뮤니티」 → 「조황」으로 바꿀지
3. **공공데이터 축소 범위**: 홈 4칸 카드를 한 줄로 줄이는 데 동의하는지, 조건 비교 화면을 메뉴에서 뺄지
4. **1단계부터 진행할지**
