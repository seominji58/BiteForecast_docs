### 1-3. 데이터 구조 (재사용할 것)
- **기록 `journal`**: 장소(필수), 일시, 어종 1, 마릿수, 최대 길이, 미끼, 채비, 메모, 사진, `trip_stop_id`, 인증 상태. 당시 날씨·해황은 `journal_env_snapshot`에 예보·실측을 구분해 저장한다.
- **글 `post`**: 분류, 제목, 본문, `place_id`(선택), 어종, `journal_id`(공유한 기록), 숨김
- **장소 `place` → 지역 `region`**: 지역은 한 단계 문자열이다(「강원 강릉시」 「부산」). 시·도는 앞 단어를 잘라서 쓴다.
- **어종 `species`**: 코드와 이름 2칸, 15종. 앱에는 21종 목록과 이미지 15장이 있다.

## 2. 낚시인의 관심사와 기존 기능의 연결

| 관심사 | 지금 있는 것 | 이을 방법 |

### 5-1. 홈
**H1. 홈 정리 (중복 버튼 제거, 지역 기준 통일)**
- 요구: 출조 판단에 필요한 핵심만 빠르게 보기
- 재사용: 지금 홈 구성(검색 → 어종 → 날짜·지역 → 지도·출조계획 → 바다 미리보기)은 그대로 둔다
- 변화:
  - 지도 버튼과 「내 주변」을 각각 하나로 줄인다.
  - 지역은 「해역 → 시·도」로 골라 지도·포인트 보기·커뮤니티 필터에 같은 값을 넘긴다.
  - 부제 두 줄을 한 줄로 줄인다.
- 데이터: 없음 (`lib/prefs.ts`의 지역 저장값을 확장)
- 난이도: 하
- 우선순위: **1순위** — 비용이 적고 모든 흐름의 출발점이다

**H2. 「최근 조황」 한 줄 (조건부)**
- 요구: 낚시 안 가는 날에도 들어올 이유
- 재사용: 조황공유 글 목록 API(시·도·어종 필터)
- 변화: 홈 맨 아래에 고른 지역·어종의 최근 조황 사진을 가로로 최대 5개 보여 준다. **글이 없으면 칸 자체를 숨긴다.** 「아직 없어요」 카드도 만들지 않는다.
- 데이터: 없음
- 난이도: 하
- 우선순위: 1순위 끝 — 공유 문턱(C1)을 먼저 낮춰야 보여 줄 글이 생긴다

### 5-2. 지도 · 낚시터 상세
**M1. 낚시터 상세의 「이용자 조황」**
- 요구: 출조 전에 이 낚시터에서 실제로 뭐가 잡혔는지
- 재사용: 글 목록 API, 사진 카드(`post-card.tsx`), 상세 화면
- 변화:
  - 상세의 지수 아래에 「이 낚시터 이용자 조황 (최근 N건)」 칸을 넣는다. 최대 3개와 「더 보기」.
  - 제목은 **「이용자 조황」**으로 하고, 예보·지수 칸과 색과 제목으로 구분한다.
  - 공개 범위가 「낚시터 이름」인 글만 넣는다.
  - 글이 0건이면 칸을 숨긴다.
- 데이터: `GET /community/posts?place_id=` 필터 추가 (DB 변경 없음)
- 난이도: 하
- 우선순위: **1순위** — 예보와 실제 조과를 잇는 핵심 연결이다

**M2. 지도에 어종 필터**
- 요구: 「우럭 잡으러 어디 가지」
- 재사용: 포인트 보기의 어종 로직(공식 지수 지점과 일반 낚시터를 나눔), 장소 정보의 대상 어종(`place_info.species` 문자열)
- 변화: 지도 위에 어종 칩을 둔다. 공식 지수 어종이면 지수 지점을 강조하고, 아니면 「어종 정보 없음」을 밝힌다.
- 데이터: 없음. 장소별 대상 어종 문자열은 품질이 고르지 않아 「참고」로만 쓴다.
- 난이도: 중
- 우선순위: 2순위 — 「포인트 보기」가 이미 어종별 목록 역할을 한다

**M3. 출입통제·위험구역 표시**
- 요구: 안전, 그리고 법적 금지와 위험 표시를 구분하기
- 재사용: 「탐험 100선」에서 받은 해경 자료(출입통제 43곳, 연안위험 820곳)와 규제 표 `restriction`(지금은 비어 있음)
- 변화:
  - 상세에 「해경 출입통제구역 안(출입 금지)」과 「연안위험구역 근처(주의)」를 **다른 색·문구**로 보여 준다.
  - 커뮤니티 글의 낚시터 태그는 「낚시 허용 장소」라는 뜻이 아니라는 문구를 넣는다.
- 데이터: 구역 자료를 넣어야 한다 (2023년 자료 ⚠ 표시 필요)
- 난이도: 중
- 우선순위: 2순위 — 100선 검증 결과와 같이 묶는다

### 5-3. 커뮤니티
**C1. 기록 공유에서 인증 필수 빼기**
- 요구: 잡은 고기를 바로 자랑하기
- 재사용: 기존 공유 흐름(`journal_id`로 글 작성, 사진·어종·장소 자동 채움), 「인증 조황」 배지
- 변화:
  - 인증받지 않은 기록도 공유할 수 있게 한다. 그 글에는 배지가 붙지 않는다.
  - 기록 저장 화면 끝에 「커뮤니티에도 올리기」 선택을 둔다(기본 꺼짐). 켜면 공개 범위를 고른다.
  - 인증은 「배지 + 포인트」를 원하는 사람만 신청한다.
- 데이터: 없음 (서비스 규칙만 바꾼다)
- 난이도: 하
- 우선순위: **1순위** — 지금 공유가 거의 일어날 수 없는 구조다. 관리자 승인을 기다려야 공유할 수 있다

**C2. 위치 공개 범위**
- 요구: 포인트는 숨기고 조과만 자랑하기
- 재사용: `post.place_id`, 지역 이름
- 변화: 글쓰기와 공유에서 「낚시터 이름 공개 / 지역만(예: 충남 태안) / 위치 숨김」 중에서 고른다. **기본값은 「지역만」.** 목록과 상세는 고른 범위만 보여 준다.
- 데이터: `post.location_visibility`(place / region / hidden), `post.region_name`(시·군 문자열 — 장소 없이 지역만 고를 때 씀). 지역 필터는 `region_name`도 함께 본다 → 장소 없는 글도 지역 필터에 걸린다.
- 주의:
  - 「낚시터 이름」은 공공 낚시터 목록의 이름일 뿐 GPS 좌표가 아니다. 사용자의 GPS 좌표는 지금도 서버로 가지 않는다.
  - 공개 범위가 「지역만」이나 「숨김」인 글은 낚시터 상세의 이용자 조황(M1)에 넣지 않는다.
- 난이도: 중
- 우선순위: **1순위**

**C3. 목록 개선 — 더 불러오기, 관심 지역·어종 기본값, 채비 질문**
- 요구: 내 지역·어종 조황을 계속 둘러보기, 초보 질문
- 재사용: 기존 필터 드롭다운, 기기에 저장된 홈 어종·지역
- 변화:
  - 맨 아래 「더 보기」로 커서 방식 페이지 넘김을 붙인다.
  - 처음 열 때 홈에서 고른 지역·어종을 필터 기본값으로 쓰고, 「전체 보기」로 풀 수 있다.
  - 분류 이름은 「조황」「질문」「정보·팁」 그대로 둔다. 질문 글쓰기에서 어종 선택을 눈에 띄게 해 「어종별 채비 질문」을 처리한다.
- 데이터: API에 `before_id` 파라미터 추가
- 난이도: 하
- 우선순위: 1순위

**C4. 공유할 때 채비 표시**
- 요구: 어떤 채비로 잡았는지
- 재사용: 기록의 `bait`·`rig`
- 변화: 공유 글 상세의 조과 요약 줄에 「미끼·채비」를 함께 보여 준다. 공유할 때 「채비 같이 보여주기」 선택(기본 켜짐).
- 데이터: `post.show_tackle`(boolean) 1칸, 또는 공유 응답에서만 처리
- 난이도: 하
- 우선순위: 2순위

**C5. 차단 · 관리자 신고 검토**
- 요구: 불쾌한 사용자 피하기, 운영자 대응
- 재사용: 신고 표 `content_report`, 관리자 페이지(`/admin`)
- 변화:
  - 글·댓글의 「…」에 「이 사용자 글 안 보기」를 둔다.
  - 관리자 페이지에 신고 목록과 「숨김 유지·해제」를 추가한다.
- 데이터: `user_block`(차단한 사람, 차단된 사람) 표
- 난이도: 중
- 우선순위: 2순위 (글이 늘기 시작하면 바로) — 공유 문턱을 낮추면 글이 늘어나서 필요해진다

### 5-4. 기록
**R1. 내 기록 요약 — 어종별 최대어 · 첫 포획 · 잡은 어종(도감)**
- 요구: 성취감, 새 어종 경험, 출조 횟수
- 재사용:
  - 기존 기록 전체
  - 서버의 어종 비교 함수(`species_key`)
  - 어종 21종 목록과 이미지 15장
  - 기록 탭 화면
- 변화: 기록 탭 맨 위에 요약 카드 하나를 두고, 누르면 「내 낚시 요약」으로 간다.
  - 출조 N일(날짜 기준) · 기록 N건 · 잡은 어종 N종
  - **잡은 어종**: 어종 이미지 격자. 잡은 어종은 컬러에 「첫 포획 날짜·최대 길이」를 보여 준다. 안 잡은 어종은 흐리게 보여 주되 「도전 과제」 문구로 압박하지 않는다.
  - **어종별 최대어**: 길이, 날짜, 기록으로 가는 링크. 인증된 기록이면 배지를 붙인다.
  - 새 기록 저장 직후 「첫 포획!」 또는 「우럭 최대어 갱신 (32→38cm)」을 한 번 보여 준다.
- 데이터: `GET /me/records/summary` (집계만, 새 표 없음). 개인 기록이므로 인증 여부와 관계없이 내 기록 전체를 대상으로 하고, 인증 여부는 표시로만 구분한다.
- 난이도: 중
- 우선순위: **2순위의 첫 번째** — 기존 데이터만으로 만들 수 있고 효과가 크다. 1순위를 2순위로 내린 이유: 공유·공개 범위가 먼저 있어야 기록할 동기가 커뮤니티로 이어진다

**R2. 꽝 기록을 자연스럽게**
- 요구: 못 잡은 날도 기록하기
- 재사용: 마릿수 0 저장 (지금도 가능)
- 변화: 기록 폼에 「오늘은 못 잡았어요」 선택을 두면 어종·길이 칸을 숨긴다. 목록에는 「꽝 · 그날 바다」로 보여 주고, 당시 해황 스냅샷을 강조한다. 출조 일수에도 포함한다.
- 데이터: 없음
- 난이도: 하
- 우선순위: 1순위 (작업이 작다)

**R3. 한 기록에 여러 어종 (무게 선택)**
- 요구: 하루 출조에서 우럭 3, 노래미 2처럼 남기기
- 재사용: 기존 기록 칸은 「대표 어종」으로 남긴다
- 변화: 기록 폼에 「어종 추가」 줄을 둔다. 줄마다 어종, 마릿수, 최대 길이, 무게(선택)를 넣는다.
- 데이터: `journal_catch`(journal_id, species_code/etc, count, max_length_cm, weight_kg) 표. 기존 기록은 1줄로 옮긴다. R1 집계와 포인트 계산도 함께 고쳐야 한다.
- 난이도: **상** (포인트·인증·공유·요약에 모두 영향)
- 우선순위: 2순위 끝 — 실제 사용 패턴을 보고 결정한다. 그 전에는 「같은 날 기록 여러 개」로 대신할 수 있다

### 5-5. 출조계획
**T1. 지난 계획 → 기록 유도 (알림 없이)**
- 요구: 다녀온 뒤 잊지 않고 기록하기
- 재사용: 장소별 「기록 남기기」, `journal_count`
- 변화:
  - 출조계획 탭 맨 위에 「어제 다녀온 『○○』 기록을 남길까요?」 카드를 하나만 보여 준다. 계획 날짜가 지났고 기록이 0개인 경우에 한하며, 닫을 수 있다.
  - 함께 간 참여자에게도 같은 카드를 보여 준다.
- 데이터: 없음
- 난이도: 하
- 우선순위: 1순위

**T2. 계획 상세에 「이 지역 최근 조황」**
- 요구: 출조 전에 관련 조황 확인
- 재사용: M1과 같은 API, 계획의 지역·목표 어종
- 변화: 다가오는 계획 상세의 장소 목록 아래에 해당 시·도·어종의 최근 조황을 최대 3개 보여 준다. 없으면 숨긴다.
- 데이터: 없음
- 난이도: 하
- 우선순위: 2순위

### 5-6. 공통 — 글씨 · 터치 · 명칭
**U1. 30~60대를 고려한 기준값**
- 요구: 읽기 쉽고 누르기 쉽게
- 재사용: `themed-text.tsx`의 글씨 종류, `form.tsx`의 버튼·칩
- 변화:
  - 글씨 기준을 small 12→**14**, 기본 14→**16**, 섹션 제목 15→**18**로 올린다.
  - 버튼·칩·목록 행의 최소 높이를 **48**로 한다.
  - 시스템 글씨 크기 설정을 따르되, 최대 배율(`maxFontSizeMultiplier` 약 1.4)로 레이아웃이 깨지지 않게 막는다.
  - 탭 라벨은 11→13으로 올린다.
- 데이터: 없음
- 난이도: 중 (모든 화면의 줄바꿈을 확인해야 한다)
- 우선순위: **1순위** — 다른 화면 개선이 모두 이 기준 위에서 이루어진다
- 주의: 연령대별 선호를 사실로 단정하지 않는다. 이 기준은 「작은 글씨·좁은 터치를 피한다」는 일반 접근성 원칙을 적용한 것이다.

## 6. 사용자 흐름 개선 (새 화면 없이 연결)

**출조 전**
- 지금: 홈 어종 → 포인트 보기 / 지도 → 상세 → 출조계획에 추가 → 계획 상세
- 바뀌는 점:
  - 홈에서 고른 지역이 지도로 그대로 이어진다(H1).
  - 상세에서 「이용자 조황」을 함께 본다(M1).
  - 계획 상세에서 최근 조황을 본다(T2).

**출조 후**
- 지금: 계획 상세 「기록 남기기」 → 기록 저장 → (인증 신청 → 관리자 승인 대기) → 공유
- 바뀌는 점:
  - 출조계획 탭 카드가 기록을 유도한다(T1).
  - 기록 저장 화면에서 바로 「커뮤니티에도 올리기 + 공개 범위」를 고른다(C1·C2).
  - 저장 직후 「첫 포획·최대어 갱신」을 보여 준다(R1).
  - 인증은 원하는 사람만 신청한다.

**평상시**
- 지금: 커뮤니티 탭 (필터를 직접 고른다)
- 바뀌는 점:
  - 커뮤니티가 내 관심 지역·어종으로 열린다(C3).
  - 홈 아래 최근 조황 줄(H2) → 글 → 낚시터 상세 → 출조계획에 추가로 이어진다.
  - 내 기록 요약에서 안 잡아 본 어종을 보고, 그 어종으로 포인트 보기를 연다.

## 9. 단계별 작업 목록

**1단계 — 기존 기능 다듬기 (DB 변경은 C2 하나)**
1. U1 글씨·터치 기준값 → 주요 화면 확인 (iOS 시뮬레이터 또는 Android 에뮬레이터 하나)
2. H1 홈 중복 버튼 정리, 지역 고르기 통일, `home-sea.tsx`·`sea-summary-card.tsx`·`SpeciesStrip` 삭제, 「포인트 보기」 이름 변경
3. C1 공유 규칙 변경 (서버·앱), 기록 저장 화면에 「커뮤니티에도 올리기」
4. C2 마이그레이션 0003(공개 범위) → 글쓰기·공유·목록·상세 반영 → **승인 후 운영 DB 적용·배포**
5. C3 더 보기·관심 기본값, M1 상세 이용자 조황(`place_id` 필터)
6. T1 지난 계획 기록 카드, R2 꽝 기록
7. H2 홈 최근 조황 줄 (글이 있을 때만)
8. 서버 테스트와 화면 확인 (maestro)

**2단계 — 성취·운영**
1. R1 `GET /me/records/summary` + 기록 탭 요약 + 저장 직후 「첫 포획·최대어」
2. C5 차단 표·관리자 신고 검토
3. C4 채비 표시, T2 계획 상세 조황
4. M2 지도 어종 칩, M3 구역 표시 (100선 검증 결과와 같이)
5. R3 여러 어종 기록 — 결정 후

**3단계 — 장기**
- 탐험 100선 도전, 동출 모집·대회는 재검토

## 10. 데이터 신뢰성 · 개인정보 원칙 (모든 안에 적용)
- 커뮤니티 글의 낚시터 태그는 **「낚시 허용 장소」를 뜻하지 않는다.** 글 상세의 장소 줄에 짧게 밝힌다.
- 해경 **출입통제구역(금지)**과 **연안위험구역(주의)**은 다른 색·문구로 구분한다. 위험구역을 금지로 표시하지 않는다.
- 위치는 「낚시터 이름 / 지역만 / 숨김」에서 고르고 기본은 「지역만」이다. 사용자 GPS 좌표는 지금처럼 서버로 보내지 않는다.
- 사진은 지금처럼 서버가 EXIF·GPS를 지운 사본만 저장하고, 원본은 남기지 않는다. 촬영 시각만 인증 참고용으로 따로 둔다.
- **예보(물때·날씨·지수)와 이용자 조황은 제목·색으로 구분한다.** 이용자 조황을 「예측」처럼 쓰지 않는다.
- 조황 글이 없으면 칸을 숨긴다. **가짜 글, 예시 글, 지어낸 통계를 만들지 않는다.** 「N명이 잡았어요」 같은 통계는 실제 글 수로만 만든다.
- 공공데이터 출처·갱신 시각 표시는 유지하되, 화면마다 반복하지 않고 상세 「자료 기준」에 모은다.
- 「낚시인0012」처럼 내부 사용자 번호가 닉네임으로 보이는 문제가 있다(`services/community.py:51`). 이제 쓰기는 로그인이 필요해서 계정이 없는 작성자는 옛 기록에만 남아 있다. 1단계에서 「낚시인」 + 무작위 표시로 바꾸는 것을 권장한다.
