## 0. 한눈에

- **지금 앱은 기능은 거의 갖췄는데, 화면의 주인공이 공공데이터다.** 기록·조황·출조계획이 각 탭에 흩어져 있어서 「남긴 기록이 남에게 보이고, 그걸 보러 다시 온다」는 고리가 약하다.
- 그래서 v2 의 핵심은 **새 기능이 아니라 순서 바꾸기**다: 이용자 조황을 홈·지도·낚시터 화면 맨 위로, 공공데이터는 「가도 될까」 확인용 요약으로.
- **새로 만들어야 하는 것은 적다**: 낚시터·지역별 조황 요약 API 하나(DB 변경 없음), 무게 칸(DB 1칸), 출입통제 자료 입력(자료 조사), 알림(나중).
- 운영 DB(2026-11-16): 사용자 20 · 기록 7 · 글 9(조황 1·질문 3, 그 외 삭제) · 댓글 0 · 좋아요 0 · 사진 6 · 인증 대기 2. **대부분 테스트 자료 — 조황이 거의 없는 상태에서 시작한다.**

## 2. 낚시인 관심사 ↔ 기존 기능

| 관심사 | 이미 있는 것 | 비어 있는 것 |
|---|---|---|
| ① 조황 인증·자랑 | 사진·어종·크기·채비, 좋아요·댓글, 위치 공개 범위, 인증 | 무게, 글 수정. **자랑한 조황이 홈·지도·낚시터에서 보이지 않음** (커뮤니티 탭 안에만) |
| ② 개인 기록·성취 | 도감·최대어·첫 포획·꽝 기록·출조 일수 | 누적 마릿수, 「올해 기록」 같은 기간 보기 |
| ③ 장비·채비 | 기록의 미끼·채비, 조황 글 채비 표시, 질문·정보 분류 | 「이 어종 사람들이 쓴 채비」 모아 보기 (기존 자료 집계로 가능) |
| ④ 지역·어종 커뮤니티 | 시·도·어종·낚시터 필터, 관심 기본값 | 글 키워드 검색, 지도·낚시터에서 그 지역 조황으로 바로 가기 |
| ⑤ 즐거움·재방문 | 최고 기록, 새 어종(도감), 동행 출조, 기록 | **남의 조과 구경**이 앱 첫 화면에 없음, 새 조황 알림 없음 |

→ 비어 있는 것의 대부분은 **새 기능이 아니라 이미 있는 조황을 앞으로 꺼내는 일**이다.

## 4. 추가하면 실제 가치가 있는 것 (적게)

1. **낚시터·지역별 조황 요약** — 모든 화면의 「조황 먼저」의 바탕. DB 변경 없음
2. **무게 칸** — 자랑·최대어에 자주 쓰는 값. 기록 1칸·글 표시
3. **글 수정** — 오타·위치 공개 범위 변경을 지우지 않고. 공개 범위를 나중에 좁힐 수 있어야 개인정보 보호에도 맞다
4. **글 키워드 검색** — 「주꾸미 에기」 같은 채비 검색
5. **출입통제구역 표시** — 안전. 자료 조사가 먼저 (아래 5-6)
6. **새 조황 알림** (나중) — 재방문의 직접 이유. 푸시 토큰 표 필요

## 5. 화면별 개선안

### 5-1. 홈

**H-A. 맨 위 「이번 주 조황」**
- 요구: 낚시 안 가는 날에도 남의 조과를 구경하고 싶다 (⑤)
- 기존 활용: H2 「최근 이용자 조황」 줄(글 있을 때만), `post-card` 썸네일, 관심 지역·어종 기본값
- 변화: 바다 배경·검색 바로 아래로 올린다. 사진 카드 가로 줄 (어종·크기·「태안군」 또는 낚시터 이름·며칠 전). 「더 보기」→ 커뮤니티 조황 목록(같은 필터). **조황 0건이면 칸을 숨기고 지금 화면 그대로**
- 데이터: 기존 `GET /community/posts?category=catch&sido=&species=` (변경 없음)
- 난이도: 하 · 우선순위: **1** — 재방문의 첫 이유, 이미 있는 부품을 옮기는 일

**H-B. 바다 정보 4칸 → 한 줄**
- 요구: 홈이 길다, 같은 정보 반복 (UX 원칙 1·4·8)
- 기존 활용: `places-summary`, 특보 판정
- 변화: `서해 · 해상 특보 없음 · 파고 최대 0.5m · 중조기 ›` 한 줄. 누르면 지도(그 해역)
- 데이터: 변경 없음 · 난이도: 하 · 우선순위: **1** — 화면 정리, 출조 판단 핵심만 남김

### 5-2. 지도 · 낚시터 카드

**M-A. 조황 있는 낚시터 핀 강조**
- 요구: 「요즘 어디서 잡혀?」 (①④)
- 기존 활용: 카카오맵 라벨(색·숫자), 핀 묶기
- 변화: 최근 14일 공개 조황이 있는 낚시터는 주황 테두리 + 건수. 나머지는 지금 색
- 데이터: 🆕 `GET /places/catch-summary?days=14` → `[{place_id, posts, species[], best_cm, last_at}]` — **공개 범위 「낚시터 이름」 글만**, 삭제·숨김·차단 제외. DB 변경 없음
- 난이도: 중 · 우선순위: **1** — 지도가 핵심 기능(원칙 2)이고, 조황을 지도에 얹는 가장 직접적인 방법

**M-B. 어종 칩 근거에 「이용자 조황」을 첫째로**
- 요구: 「우럭 잡으러 어디 가지」 (④)
- 기존 활용: 오늘 만든 어종 칩(공식 지수 지점 + 낚시터 안내 어종)
- 변화: 근거 순서 ① 이용자가 그 어종 조황을 올린 곳 → ② 공식 지수 지점 → ③ 낚시터가 알린 대상 어종. 칩 아래 안내에 근거별 곳 수 (`우럭 12곳 · 이용자 조황 3 · 공식 지수 근처 6 · 낚시터 안내 3`)
- 데이터: M-A 요약에 어종 포함 · 난이도: 하(M-A 이후) · 우선순위: **1**

**M-C. 핀 카드 맨 위 조황 한 줄**
- 변화: `최근 조황 3건 · 우럭 32cm (2일 전) ›` → 낚시터 상세의 조황 칸으로. 그 아래 특보·파고 한 줄
- 데이터: M-A · 난이도: 하 · 우선순위: **1**

### 5-3. 낚시터 상세

**P-A. 순서: 이용자 조황 → 가도 될까 → 자세히**
- 요구: 예측과 실제 조황을 구분해 보되, 실제가 먼저 (원칙: 예측·조황 구분)
- 기존 활용: M1 조황 칸, 특보 배너, 해황 그래프
- 변화: ① 이용자 조황(사진 카드, 「이용자 조황 — 예보가 아니에요」) ② 「가도 될까」 요약(특보·파고·풍속·물때 한 줄씩) ③ 그래프·관측소·지수 상세는 접기. 「여기서 기록 남기기」 버튼을 위로
- 데이터: 변경 없음 · 난이도: 중(화면 재배치) · 우선순위: **1**

### 5-4. 커뮤니티

**C-A. 조황 사진이 먼저 보이는 목록**
- 요구: 조황 사진과 지역·어종이 한눈에 (원칙 3)
- 기존 활용: `post-card`(썸네일·어종·지역 있음)
- 변화: 조황 분류는 사진 크게(카드 폭), 질문·정보는 지금처럼 글 줄. 탭 이름 「커뮤니티」→「조황」은 **결정 필요**
- 데이터: 변경 없음 · 난이도: 하 · 우선순위: **2** — 글이 쌓여야 효과

**C-B. 글 수정**
- 요구: 오타·위치 공개 범위를 나중에 바꾸기 (개인정보)
- 기존 활용: 글쓰기 화면 재사용
- 변화: 내 글 「수정」 → 같은 글쓰기 화면. 위치 공개 범위는 **좁히는 쪽은 언제나**, 넓히는 쪽도 가능
- 데이터: 🆕 `PATCH /community/posts/{id}` (`updated_at` 칸은 이미 있음, DB 변경 없음)
- 난이도: 하 · 우선순위: **1** — 위치 공개 원칙을 지키려면 필요

**C-C. 키워드 검색**
- 요구: 채비·장비 질문 찾기 (③)
- 변화: 목록 위 검색창. 제목·본문
- 데이터: `GET /community/posts?q=` (DB 변경 없음, 글 수가 적어 LIKE 로 충분)
- 난이도: 하 · 우선순위: **2**

**C-D. 「이 어종 채비」 모아 보기**
- 요구: 어종별 추천 채비 (③) — 쇼핑몰·장비 DB 없이
- 기존 활용: 공유 조황의 미끼·채비(`show_tackle` 켠 것만)
- 변화: 어종 필터를 걸면 목록 위에 「이 어종 조황에 쓴 채비: 에기 5 · 웜 3」 한 줄. 누르면 그 글들
- 데이터: 집계만 (DB 변경 없음) · 난이도: 중 · 우선순위: **3** — 채비가 적힌 조황이 쌓인 뒤

### 5-5. 기록

**R-A. 저장할 때 공유 기본값**
- 요구: 기록 → 조황 전환을 쉽게 (흐름 「출조 후」)
- 기존 활용: 「커뮤니티에도 올리기」 스위치, 위치 공개 범위
- 변화: 스위치 **기본 켜짐 + 위치 「지역만」 기본** (결정 필요). 끄면 나만 보기
- 데이터: 앱 기본값만 · 난이도: 하 · 우선순위: **1** — 조황이 쌓이는 입구

**R-B. 무게 칸**
- 요구: 무게 자랑·기록 (①)
- 변화: 기록 「최대 길이」 옆 「무게(kg, 선택)」. 조황 글·도감에 표시. 최대어는 지금처럼 길이 기준
- 데이터: 🆕 `journal.max_weight_kg` 1칸 (마이그레이션 0006, **승인 후**)
- 난이도: 하 · 우선순위: **2**

**R-C. 활동 요약 보강**
- 요구: 누적 조과, 올해 기록 (②)
- 기존 활용: `/me/records/summary`
- 변화: 내 낚시 요약에 「누적 마릿수」「올해 출조 ○일」. 랭킹·남과 비교 없음
- 데이터: 같은 API 에 집계 추가 · 난이도: 하 · 우선순위: **2**

**R-D. 사진 인증 간소화**
- 요구: 인증 과정 간소화
- 현재: 공유에는 이미 인증 불필요. 남은 문제는 **운영자 승인 대기**(지금 2건)
- 변화: 관리자 화면에 대기 건수 표시, 하루 1회 확인을 운영 절차로. 앱에는 「검토 중(보통 1일)」 안내. 자동 승인은 하지 않음(포인트 악용)
- 데이터: 변경 없음 · 난이도: 하 · 우선순위: **2**

### 5-6. 안전 (모든 화면)

**S-A. 출입통제구역·연안위험구역 구분 표시**
- 요구: 조황 장소를 낚시 허용 장소로 오해하지 않게, 법적 통제와 위험구역 구분
- 현재: `restriction` 표 0건, 종류에 「연안위험구역」 없음. 화면은 「목록의 장소를 낚시 허용구역으로 보증하지 않습니다」 문구뿐
- 변화: 낚시터 상세·지도 카드에 「출입통제구역(법적 금지)」과 「연안위험구역(위험 경고)」을 **다른 색·다른 문구**로. 자료가 없는 곳은 「확인 안 됨」 (「안전」이라 하지 않음)
- 데이터: 🆕 해역별 고시 조사 → `restriction` 입력. 종류 구분에 `coastal_danger` 추가 여부 결정(enum 변경 = 마이그레이션, **승인 후**). 100선 통제구역 조사와 같이
- 난이도: 상(자료 조사) · 우선순위: **2** — 안전 문제지만 자료 조사가 먼저라 1단계에 못 넣음

## 6. 이용 흐름 (새 화면 없이 잇기)

**출조 전**: 홈 「이번 주 조황」/어종 칩 → 지도(조황 있는 핀) → 핀 카드 「최근 조황 3건」 → 낚시터 상세(조황 → 가도 될까) → 「출조계획에 추가」 → 계획 상세 「장소」 탭(이용자 조황·해황)

**출조 후**: 계획 상세 장소 「기록 남기기」(장소·날짜 미리 채움) → 사진·어종·크기(꽝도) → 저장 → 「첫 포획·최대어」 표시 → **공유 기본 켜짐·지역만** → 그 해역 홈·지도에 조황으로 보임

**평상시**: 홈 「이번 주 조황」 → 글 상세(좋아요·댓글) → 채비 궁금하면 질문 분류 글 → 즐겨찾기 낚시터 → (2단계) 관심 낚시터 새 조황 알림 → 다음 출조계획

## 9. 단계별 작업 목록

**1단계 — 조황을 앞으로 (DB 변경 없음)**
1. 백엔드: `GET /places/catch-summary`, `PATCH /community/posts/{id}` + 테스트 → **배포 승인** (대기 중인 `info_species` 와 함께)
2. 지도: 조황 핀 강조(M-A), 어종 칩 근거 ①(M-B), 핀 카드 조황 한 줄(M-C)
3. 낚시터 상세 재배치(P-A)
4. 홈: 「이번 주 조황」 위로(H-A), 바다 정보 한 줄(H-B)
5. 기록 저장 공유 기본값(R-A), 내 글 수정(C-B)
6. 조건 비교·조건으로 찾기 진입점 정리 (3장)
7. 시뮬레이터 확인(조황 0건 상태 · 몇 건 있는 상태 모두), 테스트

**2단계 — 기록 보강·커뮤니티**
8. 무게 칸(마이그레이션 0006, 승인 후)
9. 활동 요약 보강, 인증 대기 운영 절차
10. 커뮤니티 조황 사진 목록, 키워드 검색, (결정 시) 탭 이름 「조황」
11. 통제·위험구역: 해역별 고시 조사 → 자료 입력 → 표시 (100선 조사와 함께)

**3단계 — 재방문**
12. 관심 낚시터·어종 새 조황 알림 (DB·푸시, 승인 후)
13. 어종별 채비 모아 보기

## 11. 정해 주셔야 할 것

1. 기록 저장 때 공유 **기본 켜짐 + 「지역만」** 으로 할지
2. 「커뮤니티」 탭 이름을 「조황」으로 바꿀지
3. 홈 바다 정보 4칸 → 한 줄, 조건 비교·조건으로 찾기 진입점 정리에 동의하는지
4. 무게 칸(마이그레이션 0006)을 2단계에 넣을지
5. 1단계 진행과 백엔드 배포(대기 중인 `info_species` 포함) 승인
