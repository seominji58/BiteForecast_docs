# 자동 수집 (Fly.io 예약 머신 · GitHub Actions 는 수동 백업)

## 2026-11-16 변경: GitHub 예약 실행 → Fly.io 예약 머신
- **이유**: GitHub 예약 실행(매시 17분)이 실제로는 **4~8시간에 한 번**만 돌았다 (11/11~11/16 실행 기록 20회). GitHub 은 예약 실행 시각을 보장하지 않는다. 앱에 「기상청 예보가 4시간 넘게 새로 발표·수집되지 않았어요」가 자주 떴다
- **지금**: Fly 앱 `biteforecast-api` 안의 머신 `collector` (`--schedule hourly`, shared-cpu-1x·512MB, `python -m app.jobs.collect`, 끝나면 꺼짐). 시각은 「매시간 그 시간 안 어딘가」 (분 단위 지정 불가)
  - 비밀값: Fly 앱 비밀값 `DATABASE_URL`, `DATA_GO_KR_API_KEY` (2026-11-16 추가, 값은 `.env` 에서 출력 없이 등록)
  - 첫 실행: 성공 219초 (예보 7,743행·부이 226행)
  - 비용: 한 번 약 4분 × 하루 24번 → 월 1달러 안팎 예상
- **GitHub Actions**: `schedule` 을 껐다. 수동 실행(Run workflow)만 백업으로 남김 — 둘이 동시에 돌지 않게
- **주의 — 배포 후 할 일**: `fly deploy` 는 이 머신의 이미지를 바꾸지 않는다. 수집 코드가 바뀐 배포 뒤에는
  `fly machine update <collector ID> --image registry.fly.io/biteforecast-api:<새 deployment 태그> --schedule hourly` 로 맞춘다 (ID: `fly machine list`)
- 확인: `fly machine list` (collector 가 stopped 면 정상 대기), `fly logs --machine <ID> --no-tail` 에서 「수집 주기 종료 state=success」

## 이전 기록 (GitHub Actions)

- 개발 Mac 자동 수집 금지 규칙은 유지하고, 수집은 GitHub Actions 에서 실행 (`backend/.github/workflows/collect.yml`)
- **매시 17분** 1회 (공개 저장소라 사용 시간 무료). main 코드만, 포크·PR 에서는 실행 안 함, 겹쳐 실행 안 함, 30분 제한
- 비밀값(Secrets): `DATABASE_URL`, `DATA_GO_KR_API_KEY` 두 개만 (주소·VWorld 등 다른 키는 올리지 않음). 로컬 `.env` 에서 읽어 출력 없이 등록
- 첫 실행(수동): 성공, 9분 (하루치 밀린 자료). 예보 7,743행·관측 504·조위 946·낚시지수 1,990·특보 1
- **공개 로그 점검**: API 키·DB 비밀번호·DB 주소·호스트 모두 로그에 없음, serviceKey 가림
- 앱: 홈 「서해 108곳 중 내 기준 충족 107곳」 후보 카드 정상 표시 ([스크린샷](../05_UX/screenshots/2026-11-10_ui검증_추가/08_Supabase_자동수집후_홈.png))

## 같이 고친 것
- 서버가 쉬던 Supabase 연결을 다시 쓰다 2분 가까이 멈춘 뒤 오류 → 5분마다 재연결, TCP keepalive, 연결 10초 제한

## 남은 점
- 수집 상태 파일(`runtime/collector-status.json`)은 Actions 실행 환경에 남아 서버가 못 봄 → 특보 「수집 실패」 구분은 서버에서 「자료 만료」로만 보일 수 있음. DB 에 상태를 두려면 표 추가(마이그레이션, 승인 필요)
- 실패 알림: GitHub 기본 메일 알림(실패 시) 사용
- 특보 칩 문구가 홈 카드에서 잘림 → 「해당 특보 없음」으로 수정 (`09_*`), 배너는 긴 설명 유지
