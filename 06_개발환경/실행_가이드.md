> **포트:** 입질예보 백엔드는 **8001** 을 쓴다 (8000 은 같은 맥의 다른 프로젝트 drawtale-backend 가 사용).

폴더 구조는 이렇게 가정한다.

## 0. 한눈에 보기 — 매일 켜는 순서

터미널 창을 아래 순서대로 연다. 각 창은 켜 둔 채로 둔다.

| 창 | 하는 일 | 명령 | 필수 |
|---|---|---|---|
| ① | 백엔드 서버 | `cd ~/Desktop/BiteForecast/backend && source .venv/bin/activate && uvicorn app.main:app --reload --host 0.0.0.0 --port 8001` | 필수 |
| ② | 공공데이터 수집 (1시간마다) | `cd ~/Desktop/BiteForecast/backend && source .venv/bin/activate && python -m app.jobs.collect --loop` | 권장 |
| ③ | 백엔드 외부 주소 (휴대폰이 다른 네트워크일 때) | `cloudflared tunnel --url http://localhost:8001` | 상황별 |
| ④ | 앱 개발 서버 (Metro) | `cd ~/Desktop/BiteForecast/frontend && npx expo start` (외부망이면 `--tunnel`) | 필수 |

그다음 ④번 창에서 **`i`** → 맥의 iPhone 시뮬레이터에 설치된 **개발용 앱(입질예보)**이 열린다.

> 2026-11-09부터 구글 로그인 때문에 **Expo Go 대신 개발용 앱**을 쓴다 (아래 3-6). 개발용 앱은 처음 한 번(그리고 네이티브 패키지가 바뀔 때만) `npx expo run:ios` 로 빌드하고, 평소에는 `npx expo start` 만 켜면 된다.

끌 때는 각 창에서 **`Ctrl + C`**.

## 2. 백엔드 서버

### 2-1. 환경변수 (`backend/.env`)
`.env` 는 git 에 올리지 않는다. 키 값은 문서·채팅에 붙여 넣지 않는다.

| 변수 | 내용 | 비고 |
|---|---|---|
| `DATA_GO_KR_API_KEY` | 공공데이터포털 인증키 하나로 국립해양조사원(물때·부이·바다낚시지수)과 기상청(단기예보·특보)을 모두 받는다 | 필수 |
| `KMA_API_KEY` | 기상청 API허브 인증키 | 현재 사용 안 함 (비워 둬도 됨) |
| `ADMIN_TOKEN` | 사진 인증 관리자 검토용 비밀값 (임의의 긴 문자열) | 없으면 관리자 기능이 막힘 |
| `MEDIA_DIR` | 업로드 사진 저장 폴더 | 기본 `./media` (git 제외) |
| `GOOGLE_CLIENT_IDS` | 구글 로그인 클라이언트 ID (웹·iOS, 쉼표 구분) | 없으면 구글 버튼 숨김 (3-7) |
| `SESSION_DAYS` | 로그인 유지 기간(일) | 기본 60 |
| `DATABASE_URL` | DB 위치 | 기본 `sqlite:///./biteforecast.db` |

`ADMIN_TOKEN` 만들기: `python3 -c "import secrets;print(secrets.token_urlsafe(24))"` 결과를 `.env` 에 `ADMIN_TOKEN=…` 로 넣는다.

### 2-2. 켜기
```bash
cd ~/Desktop/BiteForecast/backend
source .venv/bin/activate
uvicorn app.main:app --reload --host 0.0.0.0 --port 8001
```
- `--reload`: 코드를 저장하면 서버가 자동으로 다시 켜진다
- `--host 0.0.0.0`: 같은 Wi-Fi 휴대폰에서도 접속 가능
- 확인: 브라우저에서 http://localhost:8001/api/v1/health → `{"status":"ok"}`
- API 문서: http://localhost:8001/docs
- 서버가 켜질 때 DB 에 **새로 생긴 테이블·컬럼만 자동으로 추가**한다 (기존 데이터는 지우지 않음)

### 2-3. 공공데이터 수집
```bash
python -m app.jobs.collect          # 한 번만
python -m app.jobs.collect --loop   # 1시간마다 계속 (창을 켜 둔다)
```
이미 받은 자료는 건너뛴다. 공공데이터포털이 연속 호출을 막으면(429) 자동으로 간격을 두고 다시 시도한다.

### 2-4. 사진 인증 관리자 화면
1. `.env` 에 `ADMIN_TOKEN` 을 넣고 서버를 다시 켠다
2. 브라우저에서 http://localhost:8001/api/v1/admin
3. 위쪽 칸에 `ADMIN_TOKEN` 값을 넣고 「연결」 → 검토 대기 목록에서 승인 / 반려(사유)

### 2-5. 점검
```bash
pytest          # 테스트
ruff check .    # 린트
```

## 3. 앱 (Expo)

### 3-1. API 주소 (`frontend/.env`)
앱이 백엔드를 어디서 찾을지 정한다. **어디서 앱을 볼지**에 따라 하나를 고른다.

| 앱을 보는 곳 | `EXPO_PUBLIC_API_URL` | 주소가 바뀌나 |
|---|---|---|
| 맥의 iPhone 시뮬레이터만 | `http://localhost:8001/api/v1` | 안 바뀜 (가장 간단) |
| 휴대폰, **같은 Wi-Fi** | `http://<맥 IP>:8001/api/v1` (맥 IP: `ipconfig getifaddr en0`) | Wi-Fi 바뀌면 바뀜 |
| 휴대폰, **다른 네트워크·학교망** | `https://<터널주소>.trycloudflare.com/api/v1` (아래 3-3) | **cloudflared 를 켤 때마다 바뀜** |

- `EXPO_PUBLIC_` 값은 앱에 그대로 들어간다. 비밀값을 넣지 않는다
- `.env` 를 바꾼 뒤에는 Expo 를 `--clear` 로 다시 켠다: `npx expo start --clear`

### 3-2. 켜기
```bash
cd ~/Desktop/BiteForecast/frontend
npx expo start            # 같은 Wi-Fi / 시뮬레이터
npx expo start --tunnel   # 휴대폰이 다른 네트워크일 때 (느림)
```
켜진 창에서:

| 키 | 동작 |
|---|---|
| `i` | 맥의 iPhone 시뮬레이터에서 열기 |
| `r` | 연결된 앱 전부 새로고침 |
| `j` | 디버거 열기 |
| `Ctrl + C` | 끄기 |

휴대폰: Expo Go 를 열고 창에 보이는 QR 코드를 찍는다 (iPhone 은 기본 카메라로 찍어도 된다).

### 3-3. 휴대폰이 다른 네트워크일 때 (현재 쓰는 방식)
1. 창 ③에서 `cloudflared tunnel --url http://localhost:8001`
2. 출력에 나오는 `https://xxxx-xxxx.trycloudflare.com` 주소를 복사
3. `frontend/.env` 의 `EXPO_PUBLIC_API_URL=https://xxxx-xxxx.trycloudflare.com/api/v1` 로 바꾼다
4. 창 ④에서 `npx expo start --tunnel --clear`
5. 확인: 브라우저에서 `https://xxxx-xxxx.trycloudflare.com/api/v1/health` 가 `{"status":"ok"}`

> cloudflared 임시 터널은 **켤 때마다 주소가 바뀐다.** 다시 켰다면 2~4 를 반복한다.
> 주소를 고정하려면 Cloudflare 계정으로 이름 있는 터널(named tunnel)을 만든다.

### 3-4. 새로고침
- 코드를 저장하면 자동 반영된다
- 수동: 시뮬레이터 화면을 한 번 클릭 → **`Cmd + R`** (또는 `Ctrl + Cmd + Z` → Reload)
- Expo 창에서 **`r`**

### 3-5. 로그인 (이메일 · 구글)
- 해황·낚시터 찾기·비교·커뮤니티 읽기는 로그인 없이 된다
- 기록·사진 인증·포인트·글쓰기·댓글·좋아요·신고는 로그인 필요 (내정보·기록 탭에 로그인 안내가 나온다)
- 이메일 가입은 바로 쓸 수 있다. 구글 로그인은 아래 3-7 설정을 마치고 개발용 앱을 다시 빌드해야 버튼이 보인다
- 로그인 없이 쓰던 기록은 처음 가입할 때 그 계정으로 그대로 이어진다

### 3-6. 개발용 앱 (development build) 빌드
Expo Go 에는 구글 로그인 같은 네이티브 기능을 넣을 수 없어서, 우리 앱 전용 개발용 앱을 시뮬레이터에 설치해 쓴다.

```bash
cd ~/Desktop/BiteForecast/frontend
npx expo run:ios --device "iPhone 17"    # 처음 10분 정도. 끝나면 시뮬레이터에 「입질예보」 앱이 설치되고 열린다
```
- **다시 빌드가 필요한 때**: 네이티브 패키지 추가·삭제, `app.json`·`app.config.js` 변경, 구글 클라이언트 ID(`EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`) 변경
- **평소**: `npx expo start` → `i` (화면 코드만 바꾸면 빌드 없이 바로 반영)
- `ios/` 폴더는 빌드할 때 자동으로 만들어진다 (git 에 올리지 않음)
- 실제 iPhone 에 설치하려면 Apple Developer 계정과 `npx expo run:ios --device` (케이블 연결) 또는 EAS 빌드가 필요하다

### 3-7. 구글 로그인 설정 (처음 한 번)
1. https://console.cloud.google.com → 프로젝트 만들기 (예: biteforecast)
2. **API 및 서비스 → OAuth 동의 화면**: 외부, 앱 이름 「입질예보」, 지원 이메일 입력, 범위는 기본(email·profile·openid)
3. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID** 를 두 개 만든다
   - 유형 「웹 애플리케이션」 (이름: biteforecast-web) → 클라이언트 ID 복사
   - 유형 「iOS」 (번들 ID: `com.seominji58.biteforecast`) → 클라이언트 ID 복사
   - (안드로이드 출시 때) 유형 「Android」 (패키지 `com.seominji58.biteforecast` + 서명 SHA-1)
4. `frontend/.env`
   ```
   EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID=<웹 클라이언트 ID>
   EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID=<iOS 클라이언트 ID>
   ```
5. `backend/.env` (쉼표로 구분, 웹·iOS 둘 다)
   ```
   GOOGLE_CLIENT_IDS=<웹 클라이언트 ID>,<iOS 클라이언트 ID>
   ```
6. 백엔드 재시작 → 개발용 앱 다시 빌드 (`npx expo run:ios`) → 로그인 화면에 「구글로 계속하기」가 보인다
7. 확인: http://<서버주소>:8001/api/v1/auth/config 가 `{"google":true,...}`

> 클라이언트 ID 는 비밀값이 아니지만(앱에 포함됨) 채팅·문서에 붙여 넣지 말고 `.env` 에만 둔다.

## 4. 자주 나는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 앱에 「요청에 실패했습니다 (530)」 | cloudflared 를 다시 켜서 터널 주소가 바뀜 | 3-3 의 2~4 반복 (새 주소를 `.env` 에 넣고 `--clear`) |
| 앱에 「서버에 연결할 수 없습니다」 | 백엔드(창 ①)가 꺼짐, 또는 `.env` 주소가 틀림 | 창 ① 확인 → `/api/v1/health` 확인 → 3-1 표대로 주소 수정 |
| 시뮬레이터에 「Could not connect to the server」 | 시뮬레이터가 꺼진 Metro 주소를 기억함 | Expo 창(④)에서 `i` 를 다시 누른다 |
| 하단 탭·아이콘 일부가 안 보임 | 터널로 이미지를 받다가 일부 실패 | `Cmd + R` 또는 Expo 창에서 `r` |
| 새 패키지 설치 후 빨간 오류 화면 | Metro 가 이전 의존성을 기억함 | Expo 를 끄고 `npx expo start --clear` |
| `Port 8081 is being used` | 다른 Expo 가 이미 켜져 있음 | 그 창을 쓰거나 끄고 다시 켠다. 다른 포트: `--port 8082` |
| `Address already in use` (8001) | 백엔드가 이미 켜져 있음 | 기존 창을 쓰거나 끄기: `lsof -ti :8001 \| xargs kill` |
| 해황 값이 비어 있음 | 수집기(창 ②)를 안 켬 | `python -m app.jobs.collect` 한 번 실행 |
| 관리자 화면 「관리자 검토가 설정되지 않았습니다」 | `ADMIN_TOKEN` 없음 | 2-4 참고 |
| 로그인했는데 「로그인이 필요해요」가 계속 나옴 | 세션 만료(60일 미사용) 또는 탈퇴한 계정 | 다시 로그인 |
| 로그인 화면에 구글 버튼이 없음 | 구글 클라이언트 ID 미설정 또는 Expo Go 로 실행 중 | 3-7 설정 후 개발용 앱으로 실행 |
| 다른 프로젝트 응답이 옴 / 포트 충돌 | 같은 맥의 다른 서버(예: drawtale-backend 가 8000 사용) | 입질예보는 **8001** 을 쓴다. 다른 프로젝트는 건드리지 않는다. `.env`·cloudflared 도 8001 로 맞춘다 |
| 「내 주변 찾기」 위치가 안 잡힘 (시뮬레이터) | 시뮬레이터에 위치가 없음 | 시뮬레이터 메뉴 Features → Location → Custom Location (예: 33.556, 126.759) |

## 5. DB 백업·초기화
- DB 파일: `backend/biteforecast.db` (git 제외)
- 백업: `cp backend/biteforecast.db backend/backups/biteforecast-$(date +%Y%m%d-%H%M%S).db`
- 스키마가 바뀌어도 **DB 를 지울 필요 없다** — 서버가 켜질 때 새 컬럼·테이블을 추가한다
- 처음부터 다시 만들 때(테스트 데이터 정리 등)만: 백업 → `rm backend/biteforecast.db` → `python -m seeds.load` → `python -m app.jobs.collect`. 사용자 기록·사진 정보가 모두 사라지므로 실제 사용자 데이터가 있으면 하지 않는다
