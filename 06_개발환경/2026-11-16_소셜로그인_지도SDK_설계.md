## 2. 지도 설계

### 2-1. 지도 부품 하나로 감싸기
지금은 두 화면이 `react-native-maps`를 직접 쓴다.
- 탐색 화면 [explore.tsx](../../frontend/src/app/explore.tsx): 핀, 같은 좌표 묶음 핀, 내 위치, 카메라 이동
- 홈 바다 카드 [home-sea.tsx](../../frontend/src/components/home-sea.tsx): 고정 지도, 색 점, 숫자 묶음, 탭하면 확대·목록

이 두 화면이 **지도 라이브러리를 모르게** 공통 부품을 만든다.

```
src/components/map/
  app-map.tsx          ← 화면은 이것만 쓴다
  types.ts             ← MapMarker, Camera, AppMapProps
  provider-kakao.tsx   ← @react-native-kakao/map 어댑터 (기본)
  provider-rnmaps.tsx  ← react-native-maps 어댑터 (예비, 검증 끝나면 제거)
  provider-naver.tsx   ← (나중) 네이버 지도 어댑터
  marker-images.ts     ← 색·종류별 마커 이미지
```

```ts
type MapMarker = {
  id: string;
  lat: number; lon: number;
  kind: 'pin' | 'dot' | 'cluster';
  tone: 'good' | 'normal' | 'bad' | 'warning' | 'selected';  // 색
  count?: number;          // 묶음 숫자
  badge?: number;          // 특보 개수 같은 작은 배지
  label?: string;          // 접근성·제목
};
type AppMapProps = {
  initialCamera: { lat: number; lon: number; zoom: number };
  markers: MapMarker[];
  interactive?: boolean;               // 홈 카드는 false
  showsUserLocation?: boolean;
  onMarkerPress?: (id: string) => void;
  onCameraIdle?: (c: { lat: number; lon: number; zoom: number; bounds: Bounds }) => void;
  ref?: { moveTo(camera, animated?): void; fitBounds(bounds, padding?): void };
};
```

- 어떤 지도를 쓸지는 `EXPO_PUBLIC_MAP_PROVIDER=kakao|rnmaps`로 고른다. 기본은 `kakao`다. 카카오맵에서 문제가 생기면 다시 빌드하지 않고 설정만 바꿔 예비 지도로 돌아갈 수 있게 한다.
- 지금 화면이 쓰는 「위도·경도 폭(delta)」 방식은 카카오맵의 「줌 레벨」과 다르다. 그래서 부품 안에서 변환하고, 화면 코드는 `moveTo`·`fitBounds`만 쓴다.

### 2-2. 카카오맵에서 바뀌는 점
| 지금 (react-native-maps) | 카카오맵 | 대응 |
|---|---|---|
| `<Marker>` 안에 RN 뷰로 색 원·숫자 풍선을 그림 | 마커(라벨)에 **이미지 + 글자만** 넣을 수 있고 RN 뷰는 못 넣음 | 색·종류별 작은 PNG를 미리 만들어 두고, 숫자는 라벨 글자로 올린다. 색 종류가 정해져 있어 이미지 10여 개면 충분하다 |
| 묶음(클러스터) | 내장 클러스터링 없음 (문서 기준) | **지금도 묶음을 JS로 직접 계산**하므로(home-sea) 그대로 쓴다. 탐색 화면의 같은 좌표 묶음도 같다 |
| `pinColor`, `title`/`description` 말풍선 | 라벨 클릭 이벤트 + 정보창 | 말풍선 대신 지금처럼 아래 카드(선택 장소)를 쓴다. 이미 그렇게 동작한다 |
| 연속 카메라 이벤트 | 시작·멈춤 이벤트만 있음 | `onCameraIdle`만 쓴다 (지금도 멈췄을 때만 필요하다) |
| 내 위치 점 | 별도 표시 필요 (미확인) | 위치 권한은 지금처럼 「내 주변 찾기」를 누를 때만 받는다. 점이 없으면 내 위치 라벨을 하나 올린다 |

### 2-3. 설정
- `app.config.ts`(지금의 app.json을 바꿈): `expo-build-properties`의 `android.extraMavenRepos`에 카카오 저장소 두 개를 넣는다.
  - `https://devrepo.kakao.com/nexus/repository/kakaomap-releases/` (지도)
  - `https://devrepo.kakao.com/nexus/content/groups/public/` (로그인 SDK가 요구하면)
- 앱이 시작할 때 `initializeKakaoMapSDK(네이티브 앱 키)`를 한 번 호출한다.
- 카카오 콘솔에서 카카오맵 「사용 설정」을 켠다.
- 무료 사용량: 지도 SDK는 하루 30만 건, 넘으면 건당 0.1원이다. 개발자 계정의 **첫 활성화 앱만** 해당한다 (2026-07-21 정책).

### 2-4. 위험과 대응
- `@react-native-kakao/map` 3.2.0은 **막 나온 첫 정식 판**이다. → 예비 지도(react-native-maps)를 남겨 두고, 탐색·홈 두 화면을 모두 확인한 뒤에 예비를 제거한다.
- Android 지도는 ARM에서만 동작한다. → Apple Silicon 맥의 기본 Android 에뮬레이터는 ARM이라 문제없다. x86 이미지는 쓰지 않는다.
- 카카오맵이 안 맞을 때 대안: 카카오맵 JavaScript API를 WebView에 띄우는 방식 (무료 하루 30만 건). 성능과 탭 반응이 떨어져 마지막 수단으로 둔다.

## 3. 로그인 설계

### 3-1. 계정 구조: 「로그인 수단」 표를 따로 둔다
지금은 `account` 표에 구글 전용 칸(`google_sub`)이 있다. 카카오·네이버가 늘어날 때마다 칸을 더하지 않도록 수단을 별도 표로 뺀다.

```
account_identity
  id            PK
  account_id    FK → account.id (계정 삭제 시 함께 삭제)
  provider      'google' | 'kakao' | 'naver'
  subject       제공자가 주는 사용자 고유 ID (구글 sub, 카카오 회원번호, 네이버 id)
  email         제공자가 「확인됨」으로 준 이메일만 (없으면 비움)
  created_at, last_login_at
  UNIQUE (provider, subject)
  UNIQUE (account_id, provider)   -- 한 계정에 같은 제공자는 하나
```

- 이메일 로그인은 지금처럼 `account.email` + `password_hash`를 쓴다 (표에 넣지 않음).
- **옮기기 (마이그레이션 0003)**: `google_sub`가 있는 계정마다 `account_identity(provider='google')` 줄을 만든다. `google_sub` 칸은 한 번 배포한 동안 그대로 두고, 다음 마이그레이션에서 지운다. 되돌리기 쉽게 하려는 것이다.
- **운영 DB를 바꾸는 작업이라 승인이 필요하다.** 이전처럼 백업한 뒤 적용한다.

### 3-2. 서버 API — 제공자 공통
| 요청 | 내용 |
|---|---|
| `GET /auth/config` | 쓸 수 있는 수단: `{ email, google, kakao, naver }` (서버 설정이 있는 것만 true) |
| `POST /auth/nonce` | 일회용 nonce 발급 (5분, 한 번만 사용). 카카오 ID 토큰의 재사용을 막는다 |
| `POST /auth/social/{provider}` | `{ token, nonce? }` → 기존 계정이면 로그인(`AuthOut`), 처음이면 `{ status: 'signup_required', email?, name? }` |
| `POST /auth/social/{provider}/signup` | `{ token, nonce?, nickname, agreements }` → 가입 + 로그인 |
| `GET/DELETE /me/identities` (나중) | 내 계정에 연결된 수단 보기·해제 (마지막 하나는 해제 못 함) |

- 기존 `POST /auth/google`, `/auth/google/signup`은 같은 처리를 부르는 **별칭으로 한동안 남긴다**.
- 로그인 뒤 흐름은 지금 구글과 같다. 세션 발급, 기기 기록 옮기기(`merge-device`), 닉네임·약관 동의를 그대로 쓴다.

### 3-3. 제공자별 토큰 검증 (서버)
| 제공자 | 앱이 서버로 보내는 것 | 서버 검증 | 고유 ID |
|---|---|---|---|
| 구글 | ID 토큰 | 지금과 같다. 구글 공개키(JWKS) 서명 + `aud` ∈ `GOOGLE_CLIENT_IDS` + 발급자 | `sub` |
| 카카오 | **OIDC ID 토큰** (콘솔에서 OpenID Connect를 켜면 로그인 응답에 함께 온다) | 공개키 `https://kauth.kakao.com/.well-known/jwks.json`(캐시) 서명 RS256 + `iss = https://kauth.kakao.com` + **`aud = 네이티브 앱 키`** (SDK로 로그인하면 SDK 초기화에 쓴 키가 aud가 된다) + `exp` + **`nonce`가 서버가 발급한 값인지** | `sub` (회원번호) |
| 네이버 (나중) | 액세스 토큰 (SDK가 ID 토큰을 주지 않는다) | 서버가 `GET https://openapi.naver.com/v1/nid/me`를 그 토큰으로 호출해 `response.id`를 받는다 | `response.id` (앱별 고유) |

- **네이버의 한계**: 이 응답만으로는 토큰이 **우리 앱(client_id)용으로 발급됐는지 확인할 수 없다.** 네이버의 토큰 검증용 공식 API가 있는지는 확인하지 못했다(미확인). 다른 앱이 받은 토큰으로 로그인을 흉내 내는 위험이 있다. 그래서 **네이버는 검증 방법을 확정한 뒤에 붙인다.** 네이버가 OIDC 정보(`nid.naver.com/.well-known/openid-configuration`)를 공개하고 있으니, ID 토큰을 받을 수 있게 되면 카카오와 같은 방식으로 바꾼다.

### 3-4. 이메일이 같은 계정을 이어 붙이는 규칙
- 제공자가 **「확인된 이메일」**이라고 알려줄 때만, 같은 이메일의 기존 계정에 자동으로 연결한다. 지금 구글 규칙과 같다.
  - 구글: `email_verified = true`
  - 카카오: 이메일을 받으려면 **비즈 앱 전환**이 필요하다. 지금은 닉네임만 받으므로 **자동 연결은 없다** → 처음 카카오로 들어오면 가입 화면(닉네임·약관)으로 간다.
- 이미 로그인한 사람이 다른 수단을 추가로 연결하는 기능(`/me/identities`)은 나중에 만든다. 그 전까지는 같은 사람이 구글과 카카오로 각각 들어오면 **계정이 두 개가 된다.** 가입 화면에 「이미 다른 방법으로 가입했다면 그 방법으로 로그인하세요」 안내를 넣는다.
- 탈퇴: 계정을 삭제하면 연결된 수단 줄도 함께 지운다. 카카오는 「연결 끊기(unlink)」를 부르는 것이 원칙이다. 서버에서 하려면 Admin 키가 필요하므로, **앱에서 SDK로 unlink를 부르는 방식**으로 Admin 키를 쓰지 않는다.

### 3-5. 앱 화면
- 로그인 화면은 `GET /auth/config`를 보고 버튼을 보여 준다. 순서: **카카오로 계속하기 · 구글로 계속하기 · 이메일로 로그인** (국내 사용자 기준)
- 카카오 버튼은 카카오 디자인 가이드(노란 배경, 말풍선 심볼, 「카카오 로그인」 문구)를 따른다. 원문은 구현할 때 확인한다.
- `src/lib/google.ts`와 같은 모양으로 `src/lib/kakao.ts`를 만든다. 네이티브 모듈이 없으면(Expo Go) 「사용 불가」로 처리해 버튼을 숨긴다.
- 로그아웃할 때 제공자 SDK 로그아웃도 함께 부른다(구글은 지금도 그렇게 한다).

## 4. 키 · 서명 (원스토어)

### 4-1. 키 목록
| 키 | 어디에 | 공개 여부 |
|---|---|---|
| 카카오 **네이티브 앱 키** | 앱(`EXPO_PUBLIC_KAKAO_NATIVE_APP_KEY`, 플러그인 설정) + 서버(`KAKAO_NATIVE_APP_KEY`, aud 확인용) | 앱에 들어가도 되는 키 |
| 카카오 **REST API 키** | 서버만 (`KAKAO_REST_KEY`, 로컬 API) | **비밀** — `EXPO_PUBLIC_`·깃·로그 금지 |
| 카카오 Admin 키 | **쓰지 않음** | — |
| 구글 웹 클라이언트 ID | 앱 + 서버 `GOOGLE_CLIENT_IDS` | 공개 |
| 구글 **Android** OAuth 클라이언트 | 구글 클라우드 콘솔에 패키지명 + SHA-1 등록만 하면 된다 (앱에 넣는 값 없음) | — |
| (나중) 네이버 Client ID / Secret | 앱 (SDK가 앱에서 Secret을 요구하는 구조) | Secret이 앱에 들어간다 — 네이버 SDK의 정해진 방식 |
| (나중) 네이버클라우드 Maps 키 ID | 앱 | 공개 |
| (나중) 네이버 API HUB 검색 키 | 서버만 | **비밀** |

### 4-2. 원스토어 서명 → SHA-1·키 해시
구글 로그인, 카카오 로그인, 카카오맵은 모두 **앱 서명 인증서의 지문**을 콘솔에 등록해야 동작한다. 그래서 원스토어 서명 방식을 먼저 정해야 한다.

| 원스토어 선택지 | 결과 |
|---|---|
| **앱 서명 사용 안 함 — 직접 서명한 APK 등록 (추천)** | 서명 키가 우리 키 하나라, 그 SHA-1을 한 번만 등록하면 된다 |
| 원스토어가 키를 만들어 관리 / 내 키 등록 (AAB 쓸 때 필수) | 원스토어 서명 화면에 나오는 **앱 서명 키** SHA-1을 등록해야 한다. 한 번 AAB로 바꾸면 APK로 되돌릴 수 없다 |

- 등록할 지문:
  - **디버그 키** (`~/.android/debug.keystore` 또는 프로젝트 debug 키): 개발용 빌드 테스트용
  - **배포 키**: 원스토어용
- 등록할 곳:
  - 구글 클라우드: Android OAuth 클라이언트(패키지 `com.seominji58.biteforecast`)에 SHA-1
  - 카카오 콘솔: Android 플랫폼에 **키 해시** (SHA-1을 Base64로 바꾼 값)
  - (나중) 네이버: 패키지명 등록 (키 해시가 필요한지는 미확인)
- 배포 키스토어 파일과 비밀번호는 **깃에 넣지 않는다.** 잃어버리면 같은 앱으로 업데이트를 낼 수 없으니 따로 백업해 둔다.
- 원스토어에서 설치한 앱에서도 구글 로그인은 패키지명 + SHA-1로 동작한다. 설치 출처를 검사한다는 문서는 없다. 다만 기기에 Google Play 서비스가 있어야 한다. 원스토어만 깔린 기기(구글 서비스 없음)에서는 구글 버튼을 숨긴다(`hasPlayServices` 실패 시).

## 5. 네이버 지역 검색 · 「네이버 플레이스」 (나중)
- **제3자에게 공개된 「네이버 플레이스」 API는 찾지 못했다.** 쓸 수 있는 공식 경로는 네이버 **지역 검색 API**다.
- 검색 API는 **네이버클라우드 API HUB로 옮겨졌다.**
  - 주소: `GET https://naverapihub.apigw.ntruss.com/search/v1/local`
  - 헤더: `X-NCP-APIGW-API-KEY-ID` / `X-NCP-APIGW-API-KEY`
  - 예전 openapi.naver.com 키는 쓸 수 없다.
- 한 번에 **최대 5건**이다. 결과에는 이름, 분류, 주소, 좌표, 네이버 링크가 오고 **전화번호는 비어 있다.**
- 사용 한도는 문서마다 다르다(하루 25,000회 / 월 775,000건). 결과를 저장해도 되는지에 대한 약관은 확인하지 못했다.
- 쓰는 방법: 카카오 로컬과 같이 **낚시터 상세를 열 때 서버가 실시간으로 조회하고, 저장하지 않고, 네이버 링크로 연결**한다. 카카오 로컬(최대 15건, 거리순, 반경 검색)을 주로 쓰고, 네이버는 보조로 둔다.

- 시뮬레이터는 하나만 띄운다. Android 에뮬레이터를 쓰는 동안 iOS 시뮬레이터는 끈다.
