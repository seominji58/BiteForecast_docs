# 내일 작업 목록 — 특보·낚시지수·추천 정확성

작성일: 2026-11-10  
대상: 입질예보 backend · frontend · docs  
원칙: 원본 좌표·좌표 품질 등급·사용자 데이터·기관 원문·안전 기준을 변경하지 않는다.

## 오늘 확인한 사례

장소 `척포항남남서(25km)`에서 다음 값이 동시에 표시됐다.

- 국립해양조사원 바다낚시지수: 11월 10일 오후 `좋음`
- 기상청 단기예보: 현재 이후 파고 최대 약 `0.5m`, 풍속 최대 약 `5.7m/s`
- 기상청 특보: `남해동부바깥먼바다` 풍랑주의보 발효 중

이는 값이 서로 덮어써지지 않은 정상적인 기관·시각·공간 범위 차이다. 낚시지수는 조황이나 안전을 예측하는 값이 아니며, 특보가 있으면 낚시지수와 무관하게 추천 후보로 처리하지 않는다.

## 내일 우선 작업

### 1. 특보 연결 정확성 정리

- 특보 원문의 `발표 시각`, `발효 해역`, `현재 유효 여부`를 상세 응답과 화면에서 확인한다.
- 장소별 특보를 `직접 적용`, `인근 해역`, `다른 해역`, `적용 해역 확인 불가`, `자료 만료`, `수집 실패`로 명확히 구분한다.
- `척포항남남서(25km)`는 선상·외해 지점이므로 `남해동부바깥먼바다` 특보가 적용될 가능성이 있음을 표시하되, 좌표 다각형을 확인하지 못한 경우 안전하다고 표현하지 않는다.
- 현재 문자열 기반 해역 매칭(`남해동부` 포함 여부)은 유지하되, 화면에 매칭된 원문 해역명을 노출해 사용자가 범위를 확인할 수 있게 하는 방안을 검토한다.

### 2. 낚시지수와 기상예보의 시간·공간 범위 표시

- 바다낚시지수: 공식 지점명, 예보일, 오전/오후, 수집 시각을 표시한다.
- 기상청 예보: 격자 코드, 격자와 장소의 거리, 발표 시각, 현재 이후 집계 범위를 기록한다.
- 파고·풍속은 서로 다른 기관의 값이므로 숫자가 다를 수 있음을 상세 화면에서 설명한다.
- 파고 `0.0m`는 결측이나 조황 예측이 아니므로 원본 정밀도를 임의로 변경하지 않는다.

### 3. 추천 후보 판정 확인

- 특보 `warning/active` 장소는 낚시지수가 `좋음`이어도 추천 후보에서 제외되는지 테스트한다.
- `내 기준에 맞는 낚시터`라는 표현을 유지하고, `추천 낚시터`가 어획 가능성으로 오해되지 않는지 확인한다.
- 동점 정렬은 API 응답 순서에 의존하지 않도록 다음 우선순위를 검토한다.
  - 기본: 파고 최대 → 풍속 최대 → `place_id` → 장소명
  - 내 주변: 거리 → 파고 최대 → 풍속 최대 → `place_id`
- 실제 조황·입질 확률·어획 가능성은 생성하지 않는다.

### 4. 화면 검증

- 특보 직접 적용 장소: 낚시지수보다 특보가 먼저 보이는지 확인
- 인근 먼바다 특보 장소: 직접 특보와 다른 문구인지 확인
- 적용 해역 확인 불가·자료 만료·수집 실패: 안전하다고 표시하지 않는지 확인
- 정상 데이터·부분 결측·전체 만료 상태에서 지도 목록과 상세 화면이 장소 자체를 숨기지 않는지 확인

## 변경 전 승인 필요 사항

다음은 원인 분석 후 별도 승인을 받은 뒤에만 구현한다.

1. 특보 매칭 결과에 `direct/nearby` 세부 상태를 추가하는 API·스키마 변경
2. 특보 해역명과 적용 근거를 상세 화면에 표시하는 UI 변경
3. 동점 정렬 기준을 backend 또는 frontend에 고정하는 변경
4. 사용자 지역·거리·낚시터 유형을 활용한 정렬·필터 개선

DB·좌표·특보 원문·기관 낚시지수 값은 수정하지 않는다. 변경이 DB 구조를 포함하면 먼저 `backend/backups/`에 백업한다.

## 검증 기준

- Backend pytest 전체 통과
- frontend TypeScript·ESLint 통과
- iOS 시뮬레이터에서 직접 특보·인근 특보·자료 만료 상태 확인
- 특보가 발효 중인 장소가 조건 충족 추천으로 노출되지 않음
- 공식 낚시지수 값은 API 원문과 일치
- 실행 시각·발표 시각·예보 대상 시각을 서로 혼동하지 않음
