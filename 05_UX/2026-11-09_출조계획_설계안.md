# 출조계획 기능 설계안 (2026-11-09)

> 상태: **1차 구현 완료 (2026-11-09, 사용자 승인 「네」 — §10 결정 요청 1~4 모두 설계안대로).** 기존 데이터는 바꾸지 않았다(새 테이블 3개 + 기록에 nullable 칸 1개).
> 결정된 것 (2026-11-09 사용자): 홈 v3 다음에 진행 · 서버·계정 저장 · 비교 기능은 삭제하지 않고 출조계획과 연결.

## 1. 목표와 차별점

- 「언제·어디로 갈지」 정한 것을 저장하고, 그 날짜의 **물때·파고·풍속·해상 특보**를 계획 안에서 계속 확인하게 한다.
- 여행 일정표 구조(날짜별 장소 목록)를 빌려오되, 각 장소에 **공공데이터 해황이 붙는 것**이 차별점.
- 출조 → 기록으로 이어지게 해서 따로 있던 홈(탐색)·비교·기록을 한 흐름으로 묶는다.

## 2. 화면별 역할 (중복 정리)

| 화면 | 역할 | 하지 않는 것 |
|---|---|---|
| 홈 | **전체 낚시터 탐색** — 날짜·권역으로 조건 맞는 곳 찾기, 지도 | 내 계획 관리 |
| 출조계획 (새 탭) | **내가 정한 날짜·장소 관리** — 일정, 장소별 그날 해황, 준비물, 기록 연결 | 전체 탐색(홈·지도로 보냄) |
| 비교 (탭에서 빠지고 화면으로 유지) | **두 곳을 같은 날 나란히** 보는 도구 | 저장 |
| 기록 | **다녀온 결과** — 조과·사진·인증 | 계획 |
| 낚시터 상세 | 한 곳의 해황 전체 | — |

하단 탭: **홈 · 출조계획 · 기록 · 커뮤니티 · 내정보** (비교 탭 → 출조계획 탭).
비교 화면(`/compare`)은 그대로 두고 아래 입구에서 연다: 계획 상세 「두 곳 비교」, 홈 「두 곳 비교」 타일, 낚시터 상세, 지도 탐색.

## 3. 기능 정의

| 기능 | 우선 | 내용 |
|---|---|---|
| 계획 만들기 | 필수 | 제목(비우면 「11/14 서산 출조」 자동), 시작~끝 날짜(최대 7일), 지역(선택), 목표 어종(선택, 기존 어종 선택 재사용), 메모 |
| 장소 추가 | 필수 | 날짜별로 낚시터 추가(하루 최대 5곳). 검색 · 즐겨찾기 · 최근 본 곳 · 지도에서 고르기. 시간(선택, 예: 06:00~10:00), 메모. 「주 장소 / 예비 장소」 구분 |
| 저장·수정·삭제 | 필수 | 계획·장소·순서 수정, 계획 삭제(소프트 삭제) |
| 해황 확인 | 필수 | 장소마다 그 날짜의 파고·풍속 예보 최대, 물때(만조·간조, 관측소 이름·거리), 특보. **예보 범위 밖이면 「예보 발표 전」** — 다른 날짜 값으로 대신하지 않고 조건 충족으로 표시하지 않음 |
| 내 기준 확인 | 필수 | 홈과 같은 내 기준(파고·풍속 상한, 특보 발효 제외)으로 「충족 / 기준 밖 / 자료 부족 / 예보 발표 전」 |
| 두 곳 비교 | 필수 | 같은 날 장소가 2곳 이상이면 「두 곳 비교」 → 기존 비교 화면(날짜 포함)으로 |
| 준비물 체크리스트 | 권장 | 기본 항목(낚싯대·릴·채비 / 미끼·보냉 / 구명조끼 / 출발 전 특보 재확인) + 직접 추가, 체크 상태 저장 |
| 출조 후 기록 연결 | 권장 | 날짜가 지난 장소에 「기록 남기기」 → 기록 작성(장소·날짜 채워짐). 작성한 기록은 계획에 연결 표시 |
| 예보 변화 알림 | 추후 | 푸시 알림 인프라 필요 — 이번 범위 밖 |
| 이동 경로·숙소·교통 | 제외 | |

## 4. 사용자 흐름

```
[홈] 후보 카드 / 선택한 낚시터 해황 / 낚시터 상세 ──「계획에 추가」──┐
[비교] 두 곳 비교 결과 ──「계획에 추가」─────────────────────────┤
[출조계획 탭] 「새 계획」 ───────────────────────────────────────┤
                                                              ▼
                        계획 만들기 (날짜·지역·어종) → 날짜별 장소 추가
                                                              ▼
              계획 상세: 날짜별 장소 카드(해황·내 기준) · 두 곳 비교 · 준비물
                                                              ▼
                        출조 날짜가 지나면 「기록 남기기」 → 기록 → (사진 인증·포인트)
```

### 로그인하지 않은 사용자

- 지금 규칙과 같다: **읽기는 누구나, 저장은 로그인 필요.**
- 출조계획 탭: 기능 설명(실제 데이터 예시 없음) + 「로그인하고 계획 만들기」.
- 「계획에 추가」를 누르면 로그인 화면으로 가고, **고르던 내용(날짜·장소)은 기기에 임시로 들고 있다가** 로그인 직후 그대로 계획 만들기 화면에 채운다. 로그인을 취소하면 임시 내용은 버린다(기기에 계획을 따로 저장하지 않음 — 저장 위치를 하나로).
- 비로그인 상태에서도 홈·비교·낚시터 상세의 해황은 그대로 볼 수 있다.

### 5-1. 출조계획 탭 (목록)

```
출조계획                                   [+ 새 계획]
다가오는 계획
┌───────────────────────────────────────┐
│ 제주 주말 낚시     11/14(토)~11/15(일) D-5 │
│ 장소 2곳 · 준비물 1/4                     │
│ 11/14 김녕 · 파고 0.8m · 풍속 6m/s · 특보 없음 │  ← 첫 장소 요약
│        (예보 범위 밖이면 「예보 발표 전」)       │
└───────────────────────────────────────┘
지난 계획 (접힘) — 기록 남긴 곳 수 표시
```

### 5-2. 계획 만들기·수정 (한 화면 폼)

제목 · 날짜(시작~끝) · 지역(선택) · 목표 어종(선택) · 메모 → 저장 후 상세로.

### 5-3. 계획 상세

```
제주 주말 낚시                                  수정
11/14(토) ~ 11/15(일) · 1박 2일 · D-5
[DAY 1 11/14 토]
  ┌ 김녕 낚시터 (주)  06:00~10:00 ───────── › ┐
  │ 파고 최대 0.8m · 풍속 최대 6m/s · 특보: 발표 전 │
  │ 만조 07:12 · 제주 관측소(18.6km) 기준·참고     │
  │ 내 기준: 충족                                │
  └──────────────────────────────────────┘
  ┌ 함덕 (예비) ... ┐
  [두 곳 비교]  [+ 장소 추가]
[DAY 2 11/15 일] ... 「예보 발표 전 — 출조 3~4일 전부터 보여드려요」
준비물 체크리스트  ○ 낚싯대·릴·채비  ● 미끼·보냉 ...  [+ 항목]
(지난 날짜) [기록 남기기]
```

### 5-4. 장소 추가 시트

검색 + 즐겨찾기 + 최근 본 곳 + 「지도에서 고르기」(기존 `explore` 의 고르기 모드 재사용). 「위치 확인 필요」 낚시터는 추가할 수 있으나 해황 대신 그 안내를 보여준다.

## 6. DB 변경 (새 테이블 3개 + 기록에 칸 1개, 기존 데이터 변경 없음)

```
trip_plan
  id PK · user_id FK app_user (CASCADE) · title varchar(60)
  start_date date · end_date date (start ≤ end, 최대 7일)
  region varchar(20) NULL · species_code FK NULL · species_etc varchar(50) NULL
  memo text NULL · created_at · updated_at · deleted_at NULL (소프트 삭제)

trip_stop
  id PK · plan_id FK trip_plan (CASCADE) · day date (계획 기간 안)
  place_id FK place · role ('main' | 'alternative') · sort_order int
  start_time time NULL · end_time time NULL · memo varchar(200) NULL

trip_checklist_item
  id PK · plan_id FK (CASCADE) · label varchar(40) · checked bool · sort_order int

journal.trip_stop_id  FK trip_stop NULL (ON DELETE SET NULL)   ← 기존 기록은 NULL 그대로
```

- 미래 날짜는 예보 범위와 관계없이 저장 가능 (최대 1년 앞까지 — 오타 방지 상한).
- 해황 값은 저장하지 않는다(볼 때마다 최신 예보로 계산). 「계획 때와 달라진 예보」는 알림 기능과 함께 추후.
- 회원 탈퇴 시 계획도 삭제(기존 탈퇴 처리에 추가). 테스트 사용자 숨김 규칙은 해당 없음(계획은 본인만 봄).
- 새 테이블은 시작 시 `create_all`, `journal.trip_stop_id` 는 기존 `_add_missing_columns` 로 추가된다. 마이그레이션 전 DB 백업.

## 7. API 변경 (모두 로그인 필요, 본인 것만)

| 메서드 | 경로 | 내용 |
|---|---|---|
| GET | `/me/trips?when=upcoming\|past` | 목록 (장소 수·준비물 진행·첫 장소 요약 포함) |
| POST | `/me/trips` | 만들기 (장소·준비물 함께 보낼 수 있음) |
| GET | `/me/trips/{id}` | 상세 (장소·준비물·연결된 기록 id) |
| PATCH | `/me/trips/{id}` | 제목·날짜·지역·어종·메모 수정 (날짜를 줄여 범위 밖이 된 장소가 있으면 400 + 목록) |
| DELETE | `/me/trips/{id}` | 소프트 삭제 |
| POST / PATCH / DELETE | `/me/trips/{id}/stops[/{stop_id}]` | 장소 추가·수정(시간·메모·역할·순서)·삭제 |
| PUT | `/me/trips/{id}/checklist` | 준비물 목록 통째로 저장 |
| GET | `/me/trips/{id}/outlook` | 장소별 그날 해황 요약: `forecast_status`(`available` · `pending` 예보 발표 전 · `past`), 파고·풍속 예보 최대, 오늘이면 특보, 물때(관측소·거리), 자료 갱신 시각 |
| POST | `/journals` (기존) | `trip_stop_id` 선택 입력 추가 — 본인 계획의 장소인지 확인 |

- `outlook` 은 기존 `_place_compare` 를 재사용하되, 기존 `/places/{id}/conditions` 가 허용하지 않는 **수집 범위 밖 날짜도 400 대신 `pending`** 으로 돌려준다(값을 만들지 않음).
- `/compare` 화면에 `date` 파라미터를 받게 해 계획 날짜 그대로 비교를 연다.

## 12. 2차 구현 · 검증 (2026-11-09, 사용자 승인)

### 변경

- **로그인 전 작성**: 계획 만들기 화면을 로그인 없이 연다. 「로그인하고 계획 만들기」를 누르면 로그인 화면으로 간다.
  - 작성 내용은 **앱 메모리의 임시 작성본**(`lib/trip-draft.ts`)에 남는다. 기기 저장은 하지 않아 앱을 완전히 끄면 사라진다.
  - 로그인은 원래 화면으로 돌아와 그대로 이어지고, 가입은 화면이 처음으로 돌아가므로 출조계획 탭의 「작성하던 계획이 있어요 · 이어서 저장」 카드로 이어 쓴다.
  - 저장에 성공하면 임시 작성본을 지운다. 계획 수정은 로그인이 필요하다.
- 출조계획 탭(비로그인): 「새 출조계획 만들기」 버튼, 저장된 계획 보기는 로그인 안내.
- D등급(위치 확인 필요) 낚시터: 계획에 넣을 수 있지만, 만들기 화면·장소 카드에 「위치가 확인되지 않은 낚시터 — 지도·거리·해황은 보여드리지 않아요」를 표시한다. 해황은 `location_check`(값 없음)이고 거리는 표시하지 않는다.
- 마이그레이션·롤백: `backend/scripts/trip_tables.py`
  - `status`: 상태 확인
  - `rollback`: 계획이 있으면 거부, `--force`. 기록 연결 칸을 비운 뒤 지우고 세 테이블을 지운다. 기록 행은 남는다.
  - 백업 복사본에서 롤백을 시험했다(기록 3건 유지 확인).
  - 백업: `backups/biteforecast-20261109-190804-before-trip-round2.db`

### 미검증 (자동화로 누를 수 없음 — 완료로 보지 않음)

시뮬레이터를 직접 눌러야 확인할 수 있다. 화면 탭 자동화 도구(Maestro·idb)는 설치하지 않았다(새 도구 설치 승인 필요).

1. 비로그인으로 「새 출조계획 만들기」 → 날짜·낚시터 고르기 → 「로그인하고 계획 만들기」 → 로그인 → 내용이 그대로인지 → 저장
2. 가입으로 같은 흐름 → 출조계획 탭 「이어서 저장」 카드 → 저장
3. 상세: 장소 추가(검색·즐겨찾기), 주/예비 바꾸기, 시간·메모, 빼기, 두 곳 비교로 이동(날짜 유지)
4. 계획 수정에서 날짜 변경 → 해황이 바뀐 날짜로 다시 계산되는지
5. 앱을 다시 열거나 다른 기기에서 로그인 → 계획 유지
6. 지난 날짜 장소 「기록 남기기」 → 장소·날짜 채워짐 → 저장 → 계획에 「기록 1개」
7. 계획 지우기 → 목록에서 사라지고 기록은 남는지
8. D등급 장소(예: 우리낚시터)를 넣었을 때 안내 문구, 거리·해황 없음
9. 화면 길이: 7일 × 5곳 계획에서 상세가 너무 길지 않은지(날짜별 접기 필요 여부)

### UX 점검 (코드 기준)

- 상세 화면은 날짜 수 × 장소 수만큼 카드가 쌓인다. 7일 × 5곳이면 35장이 되어 길어질 수 있다. → 실제 화면을 확인한 뒤 「날짜별 접기」를 검토한다(미구현).
- 장소 카드는 이름 · 위치 정확도(대략·확인 필요일 때만) · 해황 한 칸 · 동작 한 줄로 최소화했다.
