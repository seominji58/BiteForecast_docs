## 1. 현재 앱의 전체 UX 문제 진단

### 1-1. 현재 구조 [확인]
- **라우팅**: Expo Router. `(tabs)`는 JS 탭(`expo-router/js-tabs`)으로 홈·비교·기록·커뮤니티·내정보 5개. Stack 화면은 `journal/new`, `journal/[id]`, `community/new`, `community/[id]`, `settings`
- **데이터**: TanStack Query → FastAPI. 홈은 `GET /places/{id}/conditions`, 비교는 `GET /compare`. 공공데이터는 서버 배치(`app.jobs.collect`)가 DB에 쌓은 값만 사용한다
- **위치**: GPS를 쓰지 않는다. `app.json`에서 Android 위치 권한을 차단했다(NFR-01). 기준 낚시터는 기기에 저장(`lib/prefs.ts`의 SecureStore)하고, 저장값이 없으면 `places[0]`을 쓴다
- **낚시터**: 219곳(`seeds/places.json`). 검색은 클라이언트에서 처리한다(`lib/place.ts` `matches`). 즐겨찾기 테이블(`favorite`)은 있지만 **API와 UI가 없다**. 최근 선택 장소도 없다
- **레이아웃**: 탭 화면은 고정 그라데이션 헤더(safe area 상단 반영)와 그 아래 ScrollView 구조다. 탭바는 불투명이라 내용과 겹치지 않는다. 커뮤니티 글쓰기 버튼은 absolute이고 목록 끝에 56px 여백이 있다

### 1-2. 실제 데이터 커버리지 [확인, 운영 DB]
| 항목 | 값 | 의미 |
|---|---|---|
| 조석 지점 연결 | 207/219 | 12곳은 물때 없음 |
| **조석 지점이 15km 넘게 떨어진 장소** | **97곳** | 물때 시각·조위가 현장과 어긋날 수 있는데, 홈 문장은 이를 알리지 않는다 |
| 부이 실측 연결 | 73/219 | 146곳은 실측 없이 예보만 있다 |
| 바다낚시지수 10km 이내 | 90/219 | 나머지는 「가까운 지수 지점 없음」 |
| 규제 정보 등록 | 0건 | 모든 장소가 「확인되지 않음」 |
| 해상 특보 | **연동 안 됨** | 기상청 API는 현재 키로 호출된다 [확인]. 오늘 07:00 기준 남해동부·서해남부 먼바다 등에 풍랑주의보 발효 중 |

### 1-3. 핵심 문제 요약
1. **안전 판단의 공식 근거(특보)가 없다** [확인]. 그런데 바다낚시지수 「매우좋음」은 크게 보여서, 사용자가 이를 "가도 된다"로 받아들일 수 있다 [추정] → **P0**
2. **기준이 무엇인지 불명확하다** [확인]. 첫 실행 기준 장소가 임의(목록 첫 번째)이고, "현재 위치가 아니라 선택한 낚시터 기준"이라는 표시가 없다
3. **데이터 대표성 안내가 부분적이다** [확인]. 홈 문장은 파고 관측소 거리만 안내하고(3km 이상일 때), 조석 지점 거리(최대 30km)는 알리지 않는다
4. **비교 요약에서 예보와 실측이 섞일 수 있다** [확인]. `describeShort()`는 장소마다 "예보 최대, 없으면 실측 최신값"을 쓰기 때문에, A는 예보·B는 실측인 상태로 나란히 보일 수 있다(`lib/describe.ts:144,146`). 사실 비교 문구(`lowerOf`)는 종류가 다르면 비교하지 않도록 이미 막혀 있다 → **P0**
5. **"언제"가 빠졌다** [확인]. 비교와 홈 모두 하루 전체 범위만 보여주고, 낚시 시간대(새벽·오전·오후·저녁) 기준이 없다
6. **장소 선택 UI가 화면마다 다르다** [확인]. 홈은 검색창, 비교는 모달 목록, **일지는 칩 219개**, 커뮤니티 글쓰기도 칩 219개
7. **같은 정보가 반복된다** [확인]. 홈의 문장, 「오늘의 주요 해황」 타일 4개, 바다낚시지수 카드(문장에도 지수가 있음)가 서로 겹친다

## 3. 사용자 시나리오

### 시나리오 1. 오늘 낚시를 갈지 판단하는 사용자
| 항목 | 내용 |
|---|---|
| 목적 | 퇴근 후(17~21시) 자주 가는 대천항에 나갈지 결정 |
| 진입 | 앱 실행 → 홈 |
| 필요한 정보 | ① 해상 특보 ② 그 시간대의 파고·풍속 예보와 내 기준 충족 여부 ③ 물때(만조·간조 시각) ④ 자료가 얼마나 가까운 곳의 것인지 |
| 행동·이동 | 홈 상단 기준 바에서 「대천항」 확인 → 특보 배너 확인 → 「오늘 시간대별」 띠에서 17~21시 확인 → (필요하면) 「다른 곳과 비교」 |
| 결과 | "특보 없음, 17~20시 내 기준 충족, 19:40 만조" → 출조 결정. 판단은 사용자가 한다 |
| 실패·부재 | 특보 해역을 알 수 없으면 「특보 확인 불가 · 기상청에서 확인」으로 표시하고, **「특보 없음」으로 표시하지 않는다**. 예보가 없는 날짜(5일 이후)는 「예보 없음」으로 표시하고 물때만 보여준다 |

### 시나리오 2. 두 낚시터 중 어디로 갈지 고민하는 사용자
| 항목 | 내용 |
|---|---|
| 목적 | 토요일 오전, 대천항과 무창포항 중 선택 |
| 진입 | 홈 「다른 곳과 비교」 또는 비교 탭 |
| 필요한 정보 | 같은 날짜·시간대 기준의 특보, 내 기준 충족 시간, 파고·풍속 최대, 물때 이벤트, 바다낚시지수(오전), 자료 거리 |
| 행동·이동 | 비교 탭 → A=대천항(자동) → B 추천 칩에서 「무창포항(9km)」 → 날짜 「토」, 시간대 「오전」 |
| 결과 | "오전 기준 충족: 대천 4시간 / 무창포 2시간, 파고 최대 0.5 vs 1.0m" 같은 **사실 비교**로 결정 |
| 실패·부재 | 한쪽만 예보가 있으면 그 항목은 비교하지 않고 「B 자료 없음」으로 표시. 실측끼리는 관측 시각이 다르면 각각의 시각을 표시하고 「더 낮은 곳」 문구는 내지 않는다 |

### 시나리오 3. 현재 위치 주변 낚시터를 탐색하는 사용자
| 항목 | 내용 |
|---|---|
| 목적 | 여행 중 근처 낚시터 찾기 |
| 진입 | 홈 기준 바 「변경」 → 장소 선택기 |
| 필요한 정보 | 가까운 순 목록, 각 장소 유형(유료/포인트/선상) |
| 행동·이동 | (P0~P1 범위) 시·도 필터나 지명 검색 → 선택 / (P2) 「내 주변」 버튼을 누를 때만 위치 권한 요청 → 거리순 정렬 |
| 결과 | 기준 낚시터가 바뀌고, 홈이 그 장소 기준으로 갱신된다 |
| 실패·부재 | 위치 권한을 거부하면 검색·시도 필터로 계속 쓸 수 있게 하고, 앱이 막히지 않는다. 주변에 등록 장소가 없으면 「이 근처에는 등록된 낚시터가 없어요」 + 가장 가까운 3곳(거리 표시) |

| 행동·이동 | 장소·일시 확인 → (선택) 조과 입력 → 저장 → 포인트·칭호 안내 → 일지 상세에서 당시 바다 조건 확인 → (선택) 「커뮤니티에 조황 공유」 |

## 6. 낚시터 비교 기능의 개선 흐름

**목적 정의**: "**같은 날, 같은 시간대에** 두 곳 중 어디가 내 조건에 더 맞는가"를 사실로 비교한다. 목적을 따로 고르게 하지 않는다. 시간대 하나로 목적을 흡수한다.

```
비교 탭 진입
 ├─ A: 기준 낚시터 자동 (변경 가능)
 ├─ B: 비어 있으면 「가까운 낚시터와 비교」 추천 칩 3개 (A에서 거리순, 같은 시·도 우선) + 「직접 찾기」
 ├─ 날짜: 오늘 ~ +4일 (예보가 있는 범위만, 그 이후는 「물때만 비교 가능」 표시)
 └─ 시간대: 새벽(04–08) · 오전(08–12) · 오후(12–17) · 저녁(17–21) · 하루  ← 기본: 오늘이면 지금 이후 첫 구간
     ↓
결과 (위에서 아래로)
 1. 특보: A/B 각 해역 특보 (있으면 해당 열 상단에 빨간 띠)
 2. 내 기준 충족 시간: 「A 3시간 / B 0시간」 + 시간 막대
 3. 시간대 핵심값 (예보끼리만): 파고 최대, 풍속 최대
 4. 물때: 시간대 안의 만조·간조 시각
 5. 바다낚시지수: 시간대에 해당하는 오전/오후 지수
 6. 수온: 실측 최신값(관측 시각 표시, 비교 문구 없음)
 7. 사실 비교 문장: 「선택한 시간대 파고 예보 최대 A 0.5m · B 1.0m」 (같은 종류·같은 시간대일 때만)
 8. 자료 기준: 각 장소의 관측소·거리·시각, A↔B 직선거리
 9. 시간별 자세히(접힘) — 현행 표 재사용
```

**규칙**
- 서로 다른 시점의 실측은 비교 문장을 만들지 않는다. 값 옆에 각각의 관측 시각만 표시한다.
- 「적합/안전」 안내는 하지 않는다. 특보는 공식 발표로만 보여주고, 그 외에는 「내 기준 충족」이라는 사용자 기준으로만 표현한다.
- 이동 거리는 GPS가 없으므로 「A↔B 직선거리」만 표시한다. 출발지 기준 거리는 P2(위치 사용 시)로 둔다.

## 7. 위치 및 관측 데이터 기준 정의

| 개념 | 정의 | 화면 표기 |
|---|---|---|
| 기준 낚시터 | 사용자가 고른 장소. 모든 해황의 기준이다. 기기에 저장 | 「선택한 낚시터 기준」 (항상 표시) |
| 현재 위치 (P2) | 「내 주변」 버튼을 누를 때만 일회성으로 사용한다. 기준 낚시터를 바꾸지 않고 **목록 정렬에만** 쓰며, 서버로 보내지 않는다 | 「내 주변 순」 |
| 관측 지점 | 부이(실측), 조위관측소(물때), 예보 격자, 지수 지점 | 지점명 + 거리 |
| 거리 등급 | ≤5km 인근 / ≤15km 참고 / ≤30km 먼 거리 / >30km 연결 안 함(현행) | 문장 끝에 「(15km 떨어진 관측소)」 |
| 시각 | 실측은 관측 시각, 예보는 발표 시각, 물때는 예측 시각 | 「15:00 실측」, 「14:00 발표 예보」 |
| 실측 vs 예보 | 현재 이전 = 실측, 이후 = 예보. 같은 줄·같은 비교 문장에 섞지 않는다 | 라벨 「실측」/「예보」 |
| 특보 | 기상청 발표만 사용한다. 장소→해상구역 매핑이 없으면 「확인 불가」 | 4상태 배너 |

**위치 권한 결론**: 현재 위치를 자동으로 적용하지 않는다. 이유는 ① 낚시터 정보는 "갈 곳" 기준이지 "지금 있는 곳" 기준이 아니고, ② 권한이 없어도 핵심 기능이 동작해야 하며, ③ NFR-01과 위치정보 처리 부담 때문이다. 「내 주변」은 P2 선택 기능으로 둔다(`expo-location` 패키지 추가, NFR-01 개정, 위치정보법 검토 필요).

## 11. 포인트·칭호 검토 [확인 기반]
- **현재 규칙**: 일지 작성 10, 어종+길이 5, 사진 5(사진 기능 미구현이라 실제로는 받을 수 없음), 첫 장소 15, 어종별 최대어 갱신 20. 칭호 5단계(0/50/150/300/600)
- **현재 쓰임**: 내정보 표시, 커뮤니티 작성자 칭호 배지
- **문제**: ① 사진 포인트는 기능이 없어 받을 방법이 없다 → 사진 기능(FR-09)을 만들기 전까지 안내에서 제외한다 ② 어떤 행동이 포인트가 되는지 작성 중에 보이지 않는다
- **제안**: 보상 체계를 늘리지 않는다. 「기록을 꼼꼼히 남기는 습관」을 위한 장치로 유지하고, 일지 작성 화면과 내정보에 획득 조건을 보여준다(P1-7, P1-8). 커뮤니티 활동 포인트는 도배를 부르므로 도입하지 않는다.
