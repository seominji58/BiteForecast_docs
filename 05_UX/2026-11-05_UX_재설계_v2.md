## 1. 현재 프론트엔드의 문제점

| 영역 | 현재 [확인] | 문제 |
|---|---|---|
| 헤더 | 탭 화면마다 로고 줄, 큰 제목(21pt), 부제가 고정되어 상단 약 110pt + safe area를 차지 (`screen.tsx` `TabScreen`) | 첫 화면 콘텐츠 영역이 좁다. 탭바에 이미 화면 이름이 있는데 제목이 중복된다 |
| 홈 | 검색창 → 장소 카드(기준 표시·특보·문장 6줄·자료 기준) → 지수 카드(어종 6줄) → 해황 타일 4개 → 가까운 낚시터 → 고지문 | 같은 수치가 문장·타일·지수에서 3번 나온다. 핵심(특보·파고·풍속)이 짧은 화면에서 한눈에 안 보인다. 다음 행동 버튼이 없다 |
| 비교 | 날짜 칩 → A/B 슬롯 → 요약 → 표 7행 → 사실 비교 → 시간별(접힘) → 출처 → 고지 | 시간대 개념이 없다. B를 매번 직접 찾아야 한다. 목적이 드러나지 않는다 |
| 기록 | 일지 폼에 장소(선택칸), 일시, **어종 칩 15개 + 기타**, 마릿수·길이·미끼·채비·메모 | 어종이 늘면 칩 방식은 유지할 수 없다. 사진·인증 흐름이 없다 |
| 커뮤니티 | 카테고리 **큰 카드 버튼 4개**, 정렬 세그먼트, 글 카드. 글쓰기 카테고리도 칩. **사진 첨부 없음** | 상단 공간을 많이 차지한다. 조황 글을 믿을 근거(사진·인증)가 없다 |
| 포인트 | **일지를 저장하면 바로 지급**(작성 10, 어종·길이 5, 첫 장소 15, 최대어 20). 「사진 +5」 규칙은 있지만 사진 기능이 없어 받을 수 없다 | 아무 기록이나 쓰면 포인트가 쌓여 칭호의 의미가 약하다. 허위 기록을 막을 장치가 없다 |
| 공통 | 카드 패딩 14, 라운드 16, 간격 16. 컬러 이미지 아이콘 + 텍스트 조작 요소. 선택 UI가 화면마다 다름(모달 목록 / 칩 / 세그먼트) | 정보 밀도가 화면마다 다르다. 같은 「고르기」가 화면마다 다르게 생겼다 |

## 2. 공통 디자인 시스템 (모든 화면에 먼저 적용)

| 항목 | 현재 | 변경 [제안] |
|---|---|---|
| 탭 화면 헤더 | 로고 줄 + 큰 제목 + 부제 (약 110pt) | **한 줄 앱바 52pt**: 왼쪽 화면 제목(17pt 굵게), 오른쪽 보조 동작(설정 등). 로고는 홈에만 작게. 그라데이션 → 단색 네이비 |
| 카드 | 패딩 14 · 라운드 16 · 그림자 | 패딩 12 · 라운드 12 · 그림자 없이 경계선 1px. 카드 사이 12 |
| 섹션 제목 | 이미지 아이콘 22 + 주황 밑줄 | 텍스트 15pt 굵게 + 오른쪽 「더보기 ›」. 밑줄 장식 제거 |
| 타이포 | 제목 21 / 섹션 16 / 값 18 / 본문 15 / 보조 13 | 화면 제목 17 · 섹션 15 · **핵심 수치 22** · 본문 14 · 보조 12 — 4단계로 고정 |
| 버튼 | 주황(주) · 틸(보조) | 주: 주황 채움 1개만(화면당) / 보조: 틸 테두리 / 텍스트 버튼: 틸 글자 |
| 선택 UI | 칩·모달·세그먼트 혼재 | **`SearchSelect` 공용 시트 하나**로 통일: 검색창 → 최근 → 목록 → 「목록에 없어요」. 장소·어종·카테고리(드롭다운 모드)에 공통 사용 |
| 짧은 선택 | 큰 카드 버튼 | **`Dropdown`**(현재값 + ▾, 누르면 작은 시트) / 2~3개는 **작은 세그먼트** |
| 안전 영역 | 상단 inset, 탭바 처리 [확인] | 유지. 앱바가 고정이라 스크롤 내용이 가려지지 않는다. 시트·고정 버튼은 `insets.bottom` 확보 |
| 작은 화면 | 확인 안 함 | iPhone SE(3세대, 375×667) 시뮬레이터로 검증. 첫 화면에 「특보 + 핵심 3수치 + 행동 버튼」이 스크롤 없이 들어가는 것을 기준으로 한다 |

## 3. 하단 5개 탭의 역할과 정보 구조

| 탭 | 한 줄 역할 | 기본 화면에 두는 것 | 상세로 보내는 것 |
|---|---|---|---|
| **홈** | 「내 낚시터, 오늘 나가도 될까?」 | 기준 낚시터·날짜·갱신 시각, **해상 특보**, 핵심 3수치(파고·풍속·수온)와 물때 다음 이벤트, 행동 버튼 2개 | 문장 설명, 바다낚시지수 어종별, 시간대별 표, 자료 기준·출처, 가까운 낚시터 → **상세 해황 화면** |
| **비교** | 「둘 중 어디로 갈까?」 | 빠른 비교(A=기준 낚시터, B 추천), 날짜·시간대, 결과 요약 | 시간별 표, 출처 |
| **기록** | 「오늘 낚시 남기기」 | 「기록 작성」 버튼, 내 기록 목록(인증 상태 배지) | 기록 상세(당시 해황, 사진, 인증 신청) |
| **커뮤니티** | 「다른 사람 조황 보기·묻기」 | 카테고리 드롭다운, 정렬, 글 목록(인증 배지) | 글 상세, 글쓰기 |
| **내정보** | 「내 활동과 인증」 | 통계, **인증 현황(대기·완료·반려)**, 포인트·칭호 | 포인트 내역, 설정 |

## 4. 홈 화면 새 구성안

### 4-1. 기존 vs 변경
| 기존 (위→아래) | 변경 (위→아래) |
|---|---|
| 큰 헤더(로고·인사·부제) | 앱바 52pt: 「입질예보」 + 「설정」 |
| 검색창 | (첫 실행에만 검색창이 주인공) |
| 장소 카드: 이름·지역·기준 표시·특보·**문장 6줄**·자료 기준 | **요약 카드 1장** (아래 4-2) |
| 지수 카드(어종 6줄) | 요약 카드 안에 「바다낚시지수 ○○」 한 줄 |
| 해황 타일 4개 | 삭제 (요약 카드와 중복) |
| 가까운 낚시터 가로 목록 | 상세 해황 화면으로 이동 |
| 고지문 | 요약 카드 하단 한 줄 |

### 4-2. 요약 카드 (스크롤 없이 한 화면, 위→아래)
```
┌───────────────────────────────────────┐
│ 대천항 ▾                    11/5(목) │  ← 누르면 SearchSelect(장소)
│ 충남 보령시 · 선택한 낚시터 기준 · 16:30 │
├───────────────────────────────────────┤
│ [특보 배너] 발효/인근/예비/없음/확인불가    │  ← P0 그대로, 숨기지 않음
├───────────────────────────────────────┤
│  파고        풍속        수온          │
│  0.5m       4.2m/s     15.9°C        │  ← 22pt
│  낮은 물결    산들바람     실측 15:00     │  ← 등급 + 실측/예보 라벨
│  예보 최대     예보 최대                   │
├───────────────────────────────────────┤
│ 물때  다음 간조 18:50 · 소조기            │
│ 바다낚시지수  감성돔 좋음 · 우럭 보통        │  ← 공식 지수, 한 줄
│ ⓘ 자료 지점 거리: 물때 관측소 25km(먼 거리) │  ← 5km 초과일 때만
├───────────────────────────────────────┤
│ [ 상세 해황 보기 ]    [ 다른 곳과 비교 ]    │  ← 보조 / 주
└───────────────────────────────────────┘
  실제 조과를 보장하지 않아요 · 출조 전 특보 확인
```
- 수치 선택 규칙: 오늘이면 **실측 최신값**(관측 시각 표시), 실측이 없으면 **남은 시간 예보 최대**(「예보 최대」 라벨). 값이 없으면 「자료 없음」. 실측과 예보를 한 칸에 섞지 않는다.
- 이 카드 아래에는 「최근 내 기록 1건」만 보조로 둔다(없으면 「첫 기록 남기기」).

### 4-3. 첫 실행 (기준 낚시터 없음)
```
오늘 낚시를 계획하고 계신가요?
어느 지역의 바다를 볼까요?
[🔍 낚시터·지역 검색           ]
자주 찾는 지역: [충남] [경남] [전남] [강원] [제주] …  ← 장소 수 많은 순
```
한 화면에서 끝낸다(질문을 단계로 나누지 않음). 고르면 저장되고, 다음 실행부터는 바로 요약 카드가 나온다.

### 4-4. 상세 해황 화면 (신규 Stack: `/place/[id]`)
지금 홈에 있던 것을 그대로 옮긴다: 지금 바다 문장(공인 등급 기준), 바다낚시지수(시간대·어종별), **시간대별 띠**(물때·파고·풍속 예보), 자료 기준(지점·거리·시각), 가까운 낚시터, 출처. 데이터는 기존 `GET /places/{id}/conditions`를 그대로 쓴다(백엔드 변경 없음).

## 5. 화면별 사용자 이동 흐름

```
홈:      (첫 실행) 목적 질문+검색 → 낚시터 선택 → 요약 카드 → [상세 해황] / [비교]
         (재방문) 요약 카드 → [상세 해황] / [비교] / 장소명 ▾ 로 변경
비교:    (A 자동) → B 추천 칩 1탭 → (선택) 날짜·시간대 → 결과 → [시간별 자세히]
기록:    [기록 작성] → 장소(기준 낚시터 미리 채움) → 어종 검색 → (선택) 사진 → [저장] 또는 [저장하고 인증 신청]
커뮤니티: 목록 → 카테고리 ▾ / 정렬 → 글 → (작성) 카테고리 ▾ · 제목 · 본문 · 사진
         · 조황 인증 글은 「인증된 내 기록 공유」로 작성 (아래 8장)
내정보:  통계 → 인증 현황(대기 n · 완료 n · 반려 n) → 포인트·칭호 → 내역
```
모든 화면의 **주 버튼은 하나**로, 다음 행동을 명확하게 한다(홈 「다른 곳과 비교」, 기록 「기록 작성」, 커뮤니티 「글쓰기」).

## 6. 비교 기능 새 UX

| | 기존 | 변경 |
|---|---|---|
| 시작 | A·B 모두 직접 선택 | **A=기준 낚시터 자동**, B는 「가까운 곳」 추천 칩 3개(A에서 거리순) 또는 검색 |
| 날짜 | 칩 11개 가로 스크롤 | `Dropdown`(오늘 기본). 예보가 없는 날짜는 「물때만 비교 가능」 표시 |
| 시간 | 없음 (하루 전체) | **시간대 세그먼트**: 새벽 · 오전 · 오후 · 저녁 · 하루. 오늘이면 지금 이후 첫 구간이 기본 |
| 목적 | 없음 | 선택형 **보기 필터**(기본은 「전체」): 「안전 조건 먼저」(특보·파고·풍속을 맨 위로, 사용자 기준 충족 시간 표시), 「가까운 곳」(A↔B 직선거리, 기준 낚시터에서 거리). 단계로 강제하지 않는다 |
| 결과 | 요약 + 표 7행 + 사실 비교 + 시간별 + 출처 | ① **특보 행**(맨 위 고정) ② 시간대 기준 파고·풍속 **예보 최대**(같은 종류일 때만 비교) ③ 수온 실측(시각 표시, 비교 문구 없음) ④ 물때: 시간대 안 만조·간조 ⑤ 바다낚시지수(해당 시간대) ⑥ 관측소 거리·신뢰 안내(거리 등급) ⑦ [시간별 자세히] ⑧ 출처 |
| 비교 불가 | 일부만 「자료 없음」 | 항목마다 「A 자료 없음 · 비교 불가」로 명시. 값을 만들지 않는다. 공통 자료 종류가 없으면 사실 비교 문장을 숨긴다(P0-3 유지) |
| 「안전」 | 표현 없음 | 앱이 안전을 판정하지 않는다. **공식 특보**와 **사용자가 정한 기준(파고·풍속) 충족 시간**으로만 보여준다 |

데이터: 기존 `GET /compare`(하루 자료)에서 시간대를 클라이언트가 잘라 쓴다. 백엔드 변경 없음.

## 7. 커뮤니티 카테고리·글쓰기 설계

| | 기존 | 변경 |
|---|---|---|
| 카테고리 | 큰 카드 버튼 4개 | 목록 상단 한 줄: `[전체 ▾]  [최신 · 인기]` — 드롭다운(전체·조황공유·낚시질문·정보·팁), 작은 세그먼트 |
| 선택 상태 | 버튼 색 | 드롭다운에 현재값 표시, 빈 결과면 「조황공유 글이 아직 없어요」 + 「전체 보기」 |
| 글쓰기 카테고리 | 칩 | `Dropdown` |
| 장소·어종 태그 | 장소 선택칸, 어종 칩 15개 | 둘 다 `SearchSelect` |
| 사진 | 없음 | **최대 4장**, 미리보기 썸네일, 각 사진 ✕ 삭제, 업로드 진행·실패 표시(재시도). 일반 글 사진은 **포인트와 무관** |
| 조황 인증 글 | 없음 | 별도 입력 양식을 만들지 않는다. **인증 완료된 내 기록을 「조황공유」로 공유**하면 글에 「인증 조황」 배지·장소·어종·마릿수·사진이 붙는다. 인증 대기 중인 기록은 공유 버튼에 「인증 후 배지가 붙어요」 안내 |

이유: 「조황 인증 글」을 커뮤니티에 따로 만들면 기록과 내용이 겹치고, 포인트 지급 경로가 두 개가 되어 중복 지급 위험이 생긴다. 인증의 주체를 **낚시일지 하나**로 둔다.

## 8. 낚시일지·어종 검색 설계

| | 기존 | 변경 |
|---|---|---|
| 장소 | `PlaceField` (P0) | 유지 (`SearchSelect` 기반으로 통일) |

## 9. 사진 인증·포인트 시스템 변경 범위

### 9-1. 현재 구조 [확인]
- 포인트: `services/points.py`가 활성 일지 **전체**로 「있어야 할 포인트」를 다시 계산해 원장과의 차이만 기록한다. 중복 지급 방지가 구조적으로 보장되는 방식이다
- 지급 사유: 작성 10 · 어종+길이 5 · 사진 5 · 첫 장소 15 · 어종별 최대어 20
- 사진: `journal_photo` 테이블만 있고 업로드 API·저장소·앱 UI가 없다
- 관리자: 역할·화면·API 없음

### 9-2. 변경 [제안]
**원칙: 포인트는 「인증 완료」 기록에서만 계산한다.** 기존 재계산 구조를 그대로 쓰고, 계산 대상만 `verification_status == approved`인 일지로 바꾼다. 인증이 반려되거나 취소되면 다음 재계산에서 자동으로 회수되고, 같은 기록은 몇 번 승인 처리돼도 한 번만 반영된다(키 = 일지 ID).

| 상태 | 의미 | 사용자 화면 |
|---|---|---|
| `none` 미인증 | 사진 없이 저장, 또는 신청 안 함 | 「개인 기록 · 포인트 없음」 |
| `pending` 인증 대기 | 사진 1장 이상 + 장소·어종 입력 후 신청 | 「검토 중」 (수정하면 다시 대기) |
| `approved` 인증 완료 | 검토자가 승인 | 「인증 완료 · +○P」, 커뮤니티 공유 시 배지 |
| `rejected` 인증 반려 | 사유와 함께 반려 | 「반려: 사유」 + 「사진 바꿔 다시 신청」 |

**인증 신청 조건**: 사진 1장 이상, 장소, 어종(목록 또는 직접 입력). 마릿수·길이는 선택이고, 입력하면 최대어 포인트 대상이 된다.

**인증 방법 (현재 기술 수준에서 실현 가능한 안)**
1. **자동 사전 검사(서버, 판정이 아니라 표시만)**
   - 같은 사진 재사용 검사: 원본 파일의 해시가 다른 기록에서 이미 승인된 사진과 같으면 표시한다
   - 촬영 시각: 사진 EXIF의 촬영 시각을 저장 전에 읽어, 출조 일시와 48시간 넘게 차이 나면 표시한다(EXIF가 없으면 「확인 불가」)
   - 개인정보: 확인 후 **EXIF 전체(GPS 포함)를 지우고** 저장한다(FR-09)
2. **사람 검토(최종 판정)**: 관리자 토큰으로 보호한 검토 API와 서버가 제공하는 간단한 검토 웹 페이지(대기 목록 → 사진·기록·사전 검사 결과 → 승인/반려+사유)
3. (후속 검토) 이미지 인식으로 「물고기 사진인지」 1차 분류 — 외부 AI API가 필요해 이번 범위에서 제외

**사진 첨부만으로는 인증 완료 처리하지 않는다.** 앱은 포인트를 직접 늘리지 않고, 항상 서버 응답의 `total_points`만 표시한다(현재도 동일 [확인]).

**기존 데이터 영향**: 변경 후 처음 재계산하면 **사진 인증이 없는 기존 일지의 포인트가 모두 회수**된다(현재는 개발 테스트 데이터뿐). 원장에 「정책 변경 회수」 행이 남는다.

| 사유 | 현재 | 변경 |
|---|---|---|
