# 어종 중심 홈 설계안 (2026-11-11, 승인 전)

> 흐름: **목표 어종 선택 → 지역·날짜 → 공식 낚시지수 → 장소 탐색 → 출조계획**
> 원칙: 공식 발표만 전달(앱이 조황·안전 점수를 만들지 않음) · 공식 지수 지점과 일반 낚시터를 섞지 않음 · 특보·좌표 품질·자료 만료 정책 유지

## 2. 홈 구성 (아래 화면의 지점·등급·수치는 모양을 보여 주는 예시예요)

```

어떤 물고기를 잡으러 가세요?                       전체 보기 ›
 ( 전체 ) (🐟우럭) (🐟감성돔) (🐟농어) (🐟돌돔) (🐟벵에돔) …   ← 좌우 스크롤, 64pt 카드
```

### 어종 카드
- 공식 지수 8종을 먼저(제공 지점 많은 순), 「전체 보기」 시트에 나머지 앱 어종 7종 — **「공식 지수 없음」** 표시, 누르면 일반 탐색(검색·조황)으로
- 이미지: `assets/species/<code>.png` (승인된 것만). 없으면 기본 아이콘 + 이름 (빈 칸 없음)
- 선택은 기기에 기억 (다음에 열면 유지), 「전체」로 해제

## 3. 정렬·표시 규칙 (점수를 만들지 않음)

공식 지수 지점 목록:
1. **특보 발효 중(warning)** 인 곳은 맨 아래 + 「특보 발효 중」 표시 (숨기지 않음 — 공식 정보이므로)
2. 선택 시간대(오전/오후/일)의 **공식 등급** 높은 순: 매우좋음 > 좋음 > 보통 > 나쁨 > 매우나쁨
3. 같으면 **파고 예보 최대** 낮은 순 → 풍속 낮은 순 → 이름순 (자료 없음은 뒤로)
4. 그 날짜에 그 어종 지수가 없는 지점은 목록에서 뺌 (「지수 없음」을 0 이나 나쁨으로 바꾸지 않음)

오전·오후: 둘 다 있으면 「오전 좋음 → 오후 보통」, 날짜가 하루(일) 단위면 토글 없이 「하루」.

근처 일반 낚시터: 지점 10km 이내만, **지점 이름·거리와 함께** 「○○ 지점의 지수 · 참고」. 위치 의심(D)·추천 보류는 넣지 않음 (기존 정책). 등급 배지는 회색 톤으로 공식 지점과 구분.

## 4. 자료 상태
- 지수 수집 시각 표시, 자료 만료면 「낚시지수 자료가 오래됐어요」 + 등급을 흐리게
- 미래 날짜에 지수 없음: 「이 날짜 지수는 아직 발표 전이에요」
- 특보 확인 불가·좌표 정책은 지금 그대로

## 5. 지도·상세·출조계획
- 「지도」: 지도 탐색을 **선택 어종의 공식 지점만** 핀으로 (지점 묶음 표시 그대로)
- 상세: 기존 낚시터 상세 (공식 지수 카드에서 선택 어종을 맨 위로)
- 출조계획에 추가: 기존 시트 그대로, 계획에 「목표 어종」 칸이 이미 있음(species_code) → 공식 지수 어종 중 기준표에 없는 3종(돌돔·벵에돔·열기)은 **기타 입력(species_etc)** 으로 저장 (DB 변경 없음)

## 6. 서버
- 새 API `GET /api/v1/fishing-index?date=` — 그 날짜 모든 지점의 어종·시간대·등급·물때 + 연결 장소(공식 지점 / 10km 이내 일반 낚시터, 거리). 한 번의 조회(Supabase 왕복 최소), 쿼리 수 상한 테스트 포함
- 파고·풍속·특보는 이미 받는 `/places-summary` 와 앱에서 합침
- DB 구조 변경 없음

## 7. 어종 이미지 (OpenAI)
- 생성: `frontend/scripts/generate-species-images.mjs` — 기본은 미리보기, `--run` 일 때만 유료 호출
- 모델 `gpt-image-2.6-flare`(빠른 반복용), 1024×1024, 투명 배경 PNG, 품질 medium 권장
- 예상: 8종 약 $0.25 (보수적 최대 $0.51) · low 약 $0.07 · high 약 $1.0 — 출력 토큰 추정값, 실제 사용량은 후보 메타에 기록
- 검수: 후보(`_candidates/`, git 제외) → 어종별 외형 체크리스트(catalog.json features) 확인 → `--approve` 로 앱 에셋 반영
- 키: `OPENAI_API_KEY`(backend/.env 또는 환경변수)만, 로그·번들·Git 에 없음
- 생성 전 OpenAI 조직 인증(Organization Verification)이 필요할 수 있음
